# Применение выпуска к выбранному серверу и общий Workspace

## Исправления

- При подготовке остановленный сервер запускается. Если контроллер уже запускает, останавливает или перезапускает сервер, подготовка ждёт завершения операции. Состояния восстановления и недоступного контроллера требуют отдельного действия.
- Папка назначения повторно проверяется при подготовке, при автоматическом входе и перед отправкой обновления. Автоматический вход проверяет адрес соединения. Уже открытое отдельное подключение игрока не меняет целевую папку выпуска.
- До отправки COMMIT сохраняется идентификатор будущего запроса. Прерванная отправка сверяется с подписанной очередью. Повторная отправка возможна по явной команде после подтверждённого отказа в том же ещё открытом раунде. Неопределённый результат не повторяется.
- Интерфейс показывает успех по подписанному состоянию конкретного выпуска. Отказ, отмена и откат отображаются отдельно. Смена поколения после обычного перезапуска сама по себе больше не считается успешным обновлением.
- В общем Workspace сервер кодирует снимок текста один раз на рассылку, независимо от количества наблюдателей того же файла. Разрешения чтения и редактирования проверяются для каждого получателя. В этом патче также есть изменения сглаживания и интервала отправки правок из 0.1.55.

## Покрытие

| Сценарий | Проверка |
| --- | --- |
| Остановлен, запущен, запускается, занят, требуется восстановление | Модель выбора действия |
| Изменение папки и адрес автоматического входа | Проверки в коде интерфейса, Windows-прогон ещё нужен |
| Повторная отправка, известный отказ, неопределённый результат | Тесты Python с подписанными записями очереди и контроллера |
| Выпуск подтверждён, откатан, принадлежит другому запуску, подпись испорчена | Тест Java на подписанном журнале |
| Публикация, три участника, транзакция обновления, рестарт, тайм-аут и откат | Интеграционный стенд Python и JVM. Игровой процесс, сохранение и Windows Job моделируются |
| Workspace | Тесты с очередью правок, подтверждениями, Unicode, курсорами, правами и повторным входом |

Ограничения текущей реализации включают автономный offline-раунд только через loopback и отсутствие применения через этот экран, если обновление не принял ни один участник. Реальные Windows-запуски, вход по домашней сети, вход друзей через интернет и производительность с двумя клиентами требуют игрового прогона.
