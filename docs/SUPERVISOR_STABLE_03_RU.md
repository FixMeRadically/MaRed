# Dev / Supervisor stable-03

История предыдущего этапа. Текущие изменения протокола/остановки/автоматики описаны в [PERFORMANCE_05_RU.md](PERFORMANCE_05_RU.md).

Это объединённый патч к приложенному MaRed, совместимый также с supervisor-rework-01 и supervisor-menu-02. Предыдущие два патча устанавливать отдельно не требуется. Работа ограничена фундаментом шагов 1–5 и его надёжностью: следующие оптимизации плана не добавляются.

## Поведение

На главном экране и в меню паузы остаётся только обычная кнопка MaRed. Welcome Preview и Dev Mode убраны; отдельной кнопки Dev Mode поверх интерфейса MaRed и F9 также нет.

После **успешного** «Применить на сервере» редактор:

1. Отличает Apply от Stop/Rollback и ошибки/отмены. Только успешный Apply запускает следующий путь.
2. Временно блокирует редактирование, сохраняет recovery-черновики всех открытых документов и состояние workspace. Ожидает завершения записи. Это не затирает исходники автосохранением.
3. Включает dev mode для текущего сеанса, переносит старые конфиги в новую структуру копированием, подготавливает состояние игрока на серверном потоке.
4. Если supervisor отсутствует, запускает его и проверяет protocol, token, instanceId, PID и WAITING_FOR_PARENT. Если уже работает, запрашивает один cooperative restart.
5. Только после подтверждения вызывает штатный Minecraft.stop(). Новый процесс ждёт выхода прежнего.
6. Один раз возвращает в тот же локальный мир или, при обычном клиентском рестарте с удалённого сервера, пытается подключиться к тому же адресу. Адрес локального мира указан явно, поэтому старая defaultWorld/autoLoad не может перенаправить этот конкретный рестарт в другой мир.

Если checkpoint, команда запуска, порт, подтверждение или сохранение намерения завершились ошибкой, клиент остаётся открытым и редактор разблокируется. Причина попадает в лог редактора и latest.log. Dev mode может остаться включённым для текущего сеанса. Повторного запуска по неудачному Apply нет.

Существующее «Применить на сервере» **разрешено только для приватного integrated server**. Это ограничение LocalScriptServerBridge оставлено: удалённый dedicated/LAN не стал принимать Java-модули. `/mared dev restart` остаётся ручной клиентской командой при уже работающем supervisor.

По выбранному пользователем поведению успешный Apply немедленно перезапускает клиент. При одиночной игре integrated server также закрывается. **Сам Java-модуль существовал в памяти и после перезапуска не остаётся активным.** Сохранённые изменения мира остаются в save, исходники/черновики остаются на диске; callbacks/tickers модуля нужно применять заново. Автоматический replay start-кода намеренно не добавлен: он мог бы повторно изменить мир. Постоянное восстановление runtime-модулей — отдельная задача.

## Runtime-файлы

Основная директория — **`<gameDir>/config/mared/dev/`**:

| Имя | Содержимое |
|---|---|
| `client.json` | controlPort; читается настоящий JSON и старый properties-формат |
| `supervisor.properties` | workDir, command.N, интервалы, auth/instance |
| `supervisor-bootstrap.jar` | Извлечённый приватный ресурс текущей сборки |
| `supervisor.lock` | Файловая блокировка одного supervisor |
| `resume.properties` | Одноразовый local/remote target; удаляется до открытия/подключения |
| `worlds.properties` | Автозагрузка/последний мир |
| `player-state.dat` | NBT-состояние игрока с привязкой к миру/UUID |
| `session.state`, `running.state` | Диагностика сессии |
| `logs/supervisor.log` | По умолчанию события и вывод ребёнка, ротация 8 МиБ + один архив `.1` |
| `logs/bootstrap.log` | Ошибки старта самой JVM/bootstrap |

Старые dev.json, supervisor.properties, dev-worlds.properties, dev-player-state.dat и .dev-state из config/mared копируются при первом обращении, если нового файла ещё нет. Исходные файлы сохраняются. Пока миграция не выполнена, чтение состояния использует старый существующий путь, новые установки сразу пишут в новую директорию. Старое resume-намерение не переносится, чтобы случайно не открыть устаревший сервер/мир. Явный пользовательский logFile и command.N сохраняются: лог может продолжить лежать по старому указанному пути. Ротация применится и к такому логу.

## Исправленные ошибки и устойчивость

- Причина размытия подтверждена по Mojang bytecode 1.21.1: Screen.render() начинает с renderBackground(). В menu-02 он вызывался после custom render MaRed и размывал готовый кадр. Добавленный тогда вызов удалён, пять MaRed-экранов наследуют MaredScreen с пустым renderBackground; глобальная настройка размытия Minecraft не меняется.
- Quickstart больше не переключает экраны из конструктора TitleScreen. Хук вызывается после init, а открытие мира откладывается до клиентского тика без загрузочного overlay.
- Нормализуется путь мира перед getFileName(): путь `.../Мир/.` раньше давал `.` и мешал выбору/сопоставлению мира.
- worlds.properties читается как UTF-8, как и записывается. Имена с управляющими символами/выходом из saves не принимаются.
- Отмена подготовки серверного модуля обрабатывает CancellationException как обычный неуспех.
- При закрытии supervisor во время spawn новосозданный процесс сразу завершается; его нельзя оставить из-за позднего присваивания child.
- Потомки завершаются по глубине родства вместо сортировки PID.
- detached supervisor не дублирует весь вывод Minecraft в bootstrap.log; основной лог ограничен ротацией.
- Сохранены подтверждение принадлежности supervisor, отказ при занятом порте, EOF latch, одна lifecycle-операция, явный ERROR вместо запуска второго клиента, таймауты/force и сохранение аргументов как command.N.

Не удаляются world/session.lock, чужие JVM, общие кэши и произвольные временные файлы. ProcessHandle отслеживает только обнаруженное дерево; очень быстро отсоединившиеся процессы требуют OS job/cgroup и не покрыты абсолютной гарантией. Gradle wrapper запускается без shared daemon.

## Проверки и практические границы

В verification находятся исходники проверок и логи. Настоящие дочерние JVM: EOF, HTTP auth/методы/точные маршруты, ошибки запуска, занятый порт, 8 конкурирующих рестартов, stop/start, bounded force, shutdown. Файловые проверки: одноразовый remote/local resume, кириллица/IPv6, TTL/PID/отмена, повреждение/путь; адаптер local/remote проверен с API doubles. Координатор проверен с API doubles для первого запуска, уже работающего supervisor и ошибки player checkpoint; проверен no-blur base. Все production Java-файлы проходят JavacTask.parse — это синтаксический анализ, не полная сборка с NeoForge.

На доступном хосте JDK 17 и скрытые ProcessHandle metadata. Успешный handoff/очистка потомков отмечаются SKIP, а отказ при недоступном ProcessHandle проверен. Для мода нужен **Java 21**. Полная Gradle-сборка, реальный GUI, штатное сохранение мира, сетевой login и cmd.exe Windows здесь не проверены. Тестовые замены игровых API этого не доказывают.

Нельзя гарантировать отсутствие обслуживания на два года: изменения Java, NeoForge, лаунчера и ОС всё равно требуют проверки. Цель рефакторинга — изолировать эти зависимости, убрать скрытые связи и оставить воспроизводимые проверки и документацию. CDS/AppCDS/watchers/ускорение чанков и следующие этапы ждут отдельной работы.

На ПК: сначала тестовый мир и копия save; Apply успешно — черновики восстановимы, новое окно одно, возвращается именно этот мир; ошибка/отмена/Stop/Rollback — без рестарта; MaRed/Welcome/Settings — чёткий текст без размытия; при занятом порте — клиент остаётся открыт. Проверять активность runtime-модуля после reboot отдельно: он не восстанавливается этим патчем.
