# Supervisor performance-05: продолжение после рабочего mod-cycle-04

Накопительный патч: исходный приложенный MaRed, rework-01, menu-02, stable-03 или mod-cycle-04. Отдельный supervisor Gradle-проект не появляется. Сохраняется рабочий цикл обычного NeoForge-мода с проверкой сборки, staging, пробным запуском, возвратом в мир и экспортом подтверждённого JAR.

## Что сделано по исходному плану

| Шаг | Состояние этого этапа |

До автоматического/ручного рестарта из редактора — сохранение мира/игроков на серверном потоке. Cleanup только собственных служебных файлов. |

Это проверяемое продолжение инфраструктуры, а не заявление о полностью выполненных шагах 6–15 или рестарте за 2–3 секунды. Последующие глубокие изменения ChunkMap/AppCDS требуют реального профилирования Minecraft.

## Быстрый restart и сохранение

Меню «Собрать и применить мод» по-прежнему сначала сохраняет исходники, успешно выполняет build и проверяет JAR. Перед закрытием серверная очередь сохраняет игроков, выполняет `saveEverything(true,true,true)`, затем сохраняет MaRed player checkpoint. Пока это не завершено, restart не отправляется. Таймаут подготовки checkpoint — прежние 10 секунд: при превышении игра остаётся открыта, поздно завершившийся save не запускает restart самостоятельно.

**Две секунды относятся к ожиданию завершения после запроса закрытия**, не к полному времени сборки/сохранения/старта. Сохранение большого мира может занять дольше. После принятого restart supervisor пишет одноразовый `shutdown.request`; новый клиент принимает только точный token/путь текущего запуска и вызывает штатный `Minecraft.stop()`. Это работает и на Windows, где `Process.destroy()` не равнозначен корректному закрытию Minecraft.

Если процесс не вышел за бюджет, supervisor завершает наблюдаемых потомков и корневой процесс, затем ждёт до пяти секунд подтверждения выхода. Процессы выбираются по владению и startInstant для потомков, не по имени java.exe. Если освобождение нельзя подтвердить, второй клиент не запускается. Учёт потомков ограничен; переполнение также блокирует следующий запуск. Сведения ProcessHandle зависят от ОС; это не Windows Job Object и не абсолютная гарантия обнаружения произвольного мгновенно отделившегося процесса. После принудительного убийства самого supervisor его потерянное дерево автоматически не восстанавливается по старым PID; перед обновлением закройте старые процессы.

Принудительное завершение не делает save безусловно безопасным: другие моды могут продолжать писать данные. Используйте тестовый мир. Откат кандидата восстанавливает JAR, а не save. Minecraft session.lock и файлы сохранений вручную не удаляются; блокировки снимает ОС после выхода владельцев. Cleanup касается только одноразового каталога этого запуска, не пользовательских temp/миров/неподтверждённых транзакций.

Нормальное закрытие пробной игры до world-ready теперь возвращает прежний JAR и остаётся в STOPPED: таймер не должен сам открывать игру после явного закрытия/Stop.

## Настройки supervisor

Файл: `<gameDir>/config/mared/dev/supervisor.properties`. Сохраните существующие `command.N`, `workDir`, `gameDir`, token и port. Для настройки добавляются/меняются только следующие ключи:

```properties
# Бюджет ожидания нормального выхода при restart; по умолчанию 2000.
restartStopBudgetMs=2000
# Для обычного /stop остаётся gracefulStopMs, по умолчанию 2000.
gracefulStopMs=2000
# off / default / dynamic. default не требует собственного архива.
cds.mode=default
# Прогрев отключён до измерения пользы на вашем ПК.
warmCache.enabled=false
warmCache.maxMs=250
warmCache.maxMiB=128
```

Конфигурация supervisor читается при его старте: для смены этих параметров закройте игру и controller, затем снова запустите MaRed и примените проект. Старый `gracefulRestartWaitMs` не управляет новым быстрым restart; используется явный `restartStopBudgetMs`. Пользователь может увеличить его для большого мира. Не копируйте пример целиком вместо настоящего конфига: в примере нет команды и токенов.

Базовый CDS сохраняет явные `-Xshare:*`, `SharedArchiveFile`, `ArchiveClassesAtExit`, включая переменные JAVA_TOOL_OPTIONS/JDK_JAVA_OPTIONS/_JAVA_OPTIONS. Поддержка описана для HotSpot JDK, в частности используемого вами Oracle JDK 21. Для другой JVM задайте `cds.mode=off`. В этом режиме supervisor не добавляет своих CDS-флагов; собственный базовый CDS JDK при этом может оставаться включённым.

### Dynamic AppCDS

Для эксперимента: `cds.mode=dynamic`. Поддерживается **прямая Java-команда с явным JAR classpath/module path или -jar**, абсолютным путём к java. Непрозрачные @argfiles, каталоги с .class, javaagent/agentpath и пользовательский system classloader отклоняются с понятной причиной в логе. Для запуска через Gradle команды не дополняются CDS-флагами, чтобы они не попали в JVM Wrapper/daemon вместо игры. Там остаётся обычное поведение CDS самого JDK. В исходном dev runClient с каталогами/argfiles динамический архив часто будет пропущен — это ожидаемо.

Первый подходящий запуск получает `ArchiveClassesAtExit`, запись публикуется только после чистого выхода с кодом 0. Следующий запуск использует совпадающий архив с `-Xshare:auto`. Ключ включает содержимое JAR, модов и JDK release/launcher, а также точные аргументы без записи их текста в лог. Отпечаток ограничен 512 МиБ/двумя секундами; при превышении остаётся базовый CDS. Удерживаются максимум несколько собственных архивов, неизвестные файлы не удаляются. Изменение мода требует нового архива. ArchiveClassesAtExit само может увеличить время выхода; двухсекундный force-stop может не дать архиву записаться.

При ненулевом завершении custom-CDS запуска supervisor отключает custom CDS до своего следующего старта. Кандидат JAR откатывается по прежнему правилу; без кандидата допускается один повторный запуск с базовым CDS. Это защитный fallback, не доказательство, что причиной был архив. Поддержка dynamic CDS проверена на настоящей маленькой JDK-программе, **не на Minecraft**. Нет утверждения, что mixin-преобразованные классы игры или мода уже попали в архив.

### Прогрев файлов

Для сравнения включите `warmCache.enabled=true`. Прогрев читает обычные JAR из `mods`, `libraries` и явно заданных class/module paths прямой Java-команды. Не разбирает @argfiles и не угадывает глобальный Gradle cache. Чтение ограничено байтами/временем/4096 записями; скрытые каталоги и saves/logs/config/screenshots не обходятся. Операции чтения ОС сами могут блокироваться; это кооперативный бюджет, не жёсткое прерывание диска. Никаких world locks или файлов мира он не удаляет. Эффект зависит от диска/RAM/кэша ОС; сравните timings до и после.

## Профиль дистанций мира — ограниченный шаг 10

Отдельный файл `<gameDir>/config/mared/dev/startup.properties`:

```properties
fastWorld.enabled=true
fastWorld.viewDistance=4
fastWorld.simulationDistance=4
```

По умолчанию профиль отключён. При dev-автовозврате в одиночный мир он временно ограничивает стандартные client render/simulation options, из которых integrated server берёт дистанции. Значения не увеличиваются, если у пользователя уже меньше. Он не пропускает обязательные загрузочные экраны, подготовку spawn, обработку forced chunks, IO мира и регистрацию мода. Нет новых mixins в ChunkMap.

Прежние значения сначала сохраняются в `world-profile-restore.properties`. При выходе из мира или штатном restart они восстанавливаются; после прерванного запуска журнал обрабатывается на title screen следующего запуска, в том числе вне dev mode. Если пользователь явно поменял значение в активном профиле, отличающееся от cap значение сохраняется. Нечитаемый/повреждённый журнал не перезаписывается новым профилем. Профиль рассчитан на стандартные опции 1.21.1; модифицированные сторонними модами диапазоны не проверены. При ручном первом открытии мира без quickstart/return профиль не навязывается.

## Автосборка и применение — шаг 11

В MaRed → Scripts → Запуск включите **«Автосборка и применение: ВЫКЛ»** для выбранного импортированного Gradle-проекта. Выбор хранится в его `genesis-project.properties` как `watch_apply=true`; после перезапуска при повторном открытии редактора восстанавливается.

- Наблюдение активно только пока открыт редактор, выбран этот проект, есть приватный одиночный мир и редактор свободен.
- Изменение должно быть **сохранено на диск**. Для IDE используйте Link либо редактируйте именно рабочую Copy-папку, показанную MaRed. Исходная папка Copy и копия не синхронизируются.
- Хеширование идёт в отдельной daemon-очереди, не в render thread. Требуются два совпавших новых отпечатка с задержкой; промежуточное сохранение нескольких файлов не запускает немедленный restart.
- Build/cache/run outputs не участвуют в отпечатке, чтобы собственный build не породил цикл. Отслеживаются исходники/ресурсы/настройки проекта; `.class` в build сами по себе не являются командой установить мод.
- Несохранённые открытые правки блокируют автоматику. Чистые открытые документы, изменённые снаружи, перечитываются перед build; чужие черновики не затираются. Build снова проверяет входы/артефакт.
- Успешный результат проходит тот же staging/checkpoint/restart. Ошибка сборки не вызывает повторных сборок без нового изменения исходников. Ошибка чтения останавливает наблюдение в текущем состоянии; причина пишется в редактор.
- Закрытие редактора/выход из мира/переключение проекта прекращают наблюдение соответствующего проекта. Это не background build service, работающий между JVM. Изменения во время закрытого редактора считаются новым исходным состоянием при включении.

## Меню и журнал времени

В том же меню — **«Перезапустить Minecraft и вернуться в мир»**. Эта команда работает и без изменения исходников, сохраняет recovery/workspace и выполняет тот же player/world checkpoint. F9 и дополнительные кнопки главного экрана не возвращаются.

`<gameDir>/config/mared/dev/logs/timings.jsonl` содержит по событию на строку. Ротация около 2 МиБ с одним previous-файлом. Есть launch UUID, UTC-время, phase, valueMs, measure и cycleMs. Аргументы запуска/аккаунта в этот журнал не попадают.

- `prepare`, `shutdown`, `spawn` — длительности (`measure=duration`). spawn включает установку/прогрев/подбор CDS и запуск launcher-процесса; для Gradle это **не** момент старта JVM Minecraft.
- `mod_loaded`, `world_loading`, `player_restored`, `world_ready` — uptime JVM игры на соответствующей отметке (`measure=jvm_uptime`). `mod_loaded` означает вход в/завершение конструктора MaRed, не полную загрузку всех модов.
- `world_load` — разность world_ready и world_loading при наличии обеих меток. `player_restore` — время вызова восстановления состояния.
- `cycleMs` — монотонное время supervisor от принятого restart. Первый handoff начинает отсчёт со старта supervisor. Предварительный build и server checkpoint до HTTP restart сюда не входят; их время видно в логе редактора/latest.log.

HTTP `/metrics` требует control token и точный launch UUID текущего ребёнка. Запоздавший отчёт старой JVM отклоняется. Показатели не объявляются бенчмарком до прогона в самой игре.

## Проверки и границы

Проверены JDK-only supervisor и все 68 core sources, реальные файлы, отдельные дочерние JVM, clean token shutdown, fallback force, HTTP/EOF/сериализация, trial rollback/confirm, Copy/Link, source watcher, динамическая CDS запись/чтение на fixture JAR, bounded warm cache и timings. World profile и normal-stop адаптер проверены с явно обозначенными doubles API Minecraft. Parser проверяет main sources, не заменяя NeoForge typecheck.

Здесь по-прежнему доступен JDK 17, а для MaRed требуется **JDK 21**. Полная сборка нового этапа, реальная скорость запуска, Windows ProcessHandle descendants и поведение нового профиля в Minecraft не проверены. Старый mod-cycle-04 вы подтвердили в игре; это не переносит автоматически подтверждение на новые изменения. После установки выполните clean build и сценарии verification/README_RU.md на своём ПК.

Официальные ограничения/справка: [Java 21 CDS](https://docs.oracle.com/en/java/javase/21/vm/class-data-sharing.html), [Java command/AppCDS](https://docs.oracle.com/en/java/javase/21/docs/specs/man/java.html), [ProcessHandle identity](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/ProcessHandle.html), [GraalVM dynamic features](https://www.graalvm.org/jdk21/reference-manual/native-image/dynamic-features/).
