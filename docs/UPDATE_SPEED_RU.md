# Ускорение обновления MaRed

Цель для полного обновления из наблюдавшихся 14 минут — 105 секунд. Замер полного цикла нужен на Windows-сервере с реальными игроками, тем же набором модов и тем же миром.

- Клиент собирает проверенную папку новых модов в отдельном каталоге до закрытия игры. Неизменившиеся JAR берутся из старого профиля и сверяются по хешу. После закрытия клиента копируются актуальные настройки и файлы профиля, а готовая папка модов переносится переименованием внутри того же каталога. Исходный профиль остаётся источником для возврата. Дополнительный дубликат старой папки модов в новом клиентском профиле больше не создаётся.
- В рамках одного вызова проверки клиента проверенный подписанный манифест используется повторно. Проверяются хеш, подпись, актуальный выпуск и соответствие серверному инвентарю.
- Первоначальный импорт серверных наборов вычисляет хеш во время копирования. Последующие проверки проверяют итоговые исходники и копию. Архиватор быстрее обрабатывает уже сжатые JAR, сохраняя формат ZIP.
- Изменения распространяются и на повторное обновление уже управляемого клиента. Допуск по-прежнему требует подтверждения фактической загрузки клиентских модов и готовности сервера.

## Где увидеть задержку

Ищи строки с префиксом `MaRed update timing:`. На сервере они пишутся в `.genesis/server104/logs/controller.log`. У клиента журнал установщика находится в `%LOCALAPPDATA%/Genesis/remote-installs70/update-*/worker70.log`. Новый тестовый раунд нужно запустить после сборки и штатного перезапуска текущего управляющего процесса. Для сравнения клиентского времени участники должны начать раунд из клиентов с новым MaRed.

Серверные замеры разделяют проверку выпуска, ожидание готовности клиентов, сохранение и остановку сервера, изменение модов и запуск нового экземпляра. Клиентский журнал разделяет подготовку до переключения, финальную проверку, закрытие игры, сборку профиля, старт клиента и вход. Стадии клиента и сервера частично перекрываются, поэтому их времена не надо складывать.

```powershell
Select-String -Path '.genesis\server104\logs\controller.log' -Pattern 'MaRed update timing:' | Select-Object -Last 20
$worker = Get-ChildItem "$env:LOCALAPPDATA\Genesis\remote-installs70\update-*\worker70.log" -ErrorAction SilentlyContinue |
  Sort-Object LastWriteTime -Descending | Select-Object -First 1
if ($worker) { Select-String -LiteralPath $worker.FullName -Pattern 'MaRed update timing:' | Select-Object -Last 20 }
```

Первую команду запускают из корня папки сервера Minecraft. Вторая выполняется на клиентском ПК.

## Дополнение по клиентскому профилю

Замер Windows показал 76,748 с на `build-profile`, 23,657 с на старт клиента и 18,719 с на итоговую проверку. После штатного закрытия повторная проверка сохраняет расчёт места, проверку путей и проверочную запись, а пробное чтение оставляет предыдущей стадии. При копировании каждый включённый файл читается и сверяется. Для конфигураций повторный хеш источника вычисляется один раз в конце копии.

Появились отдельные строки `final-storage-check`, `final-auth-check`, `closed-profile-space-check`, `copy-client-profile` и, для runClient, `copy-dev-snapshot`. Они вложены в прежние итоговые замеры. Эффект на Windows нужно измерить в следующем обычном обновлении. Состав подписанных выпусков эти изменения не меняют.

## Автоматический переход и окно обновления

При штатном «Применить на выбранный сервер» контроллер сам отправляет COMMIT после ответов игроков и готовности принявших участников. В этой операции разрешение получено при запуске применения. Устаревший контроллер может использовать прежнюю отправку COMMIT через вызывающий процесс. Сетевые разрешения для ручных команд сохраняются.

После COMMIT сервер предоставляет до 30 секунд для завершения установки клиентами. При исправном управляющем канале сервер запускается с новым выпуском по истечении этого интервала. Доступ конкретного клиента по-прежнему зависит от установки, а общий допуск открывается по прежнему порогу. При недоступном управляющем канале сохраняется сценарий восстановления прежнего выпуска. В журнале интервал называется `server-client-install-grace`. Время скачивания до COMMIT, сохранения мира и запуска JVM в этот интервал не входит.

Заставка теперь в обычном окне с рамкой, Core-анимацией, кнопками «Свернуть» и «Остановить…». Escape сворачивает окно. Подтверждение остановки относится к отмене операции самим игроком.

Стенд проверяет запуск нового экземпляра до завершения установки, закрытый допуск до подтверждения и открытие допуска после установки. Реальный запуск Minecraft на Windows и вид окна отдельно не проверены.
