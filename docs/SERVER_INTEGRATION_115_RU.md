# Подключение существующих систем: патч115

## Что теперь связано

Script → успешная сборка → меню артефакта → «Применить на этом сервере…» →
проверенный BuildSnapshot84 → обзор JAR → подтверждение → подписанная локальная очередь →
текущий owner104 → сохранение и штатная остановка → Changes104 → новый запуск с READY.

Раньше этот пункт меню только сохранял путь JAR в старые настройки66 и открывал
ServerSetupLauncher59. Нынешняя простая панель104 этот путь не читала: до применения дело не доходило.
Теперь путь66 не используется для этого действия. Старый подписанный мастер84 обозначен расширенным.

## Как проверить в Minecraft

1. Установить патч, собрать `gradlew.bat build`, запустить обновлённый клиент.
2. Если сервер уже работал со старым контроллером — штатно остановить его и запустить
   из простой панели Genesis. Это обновляет встроенный контроллер; старый живой процесс
   не получает новый код от простой пересборки. Не закрывать консоль kill/Task Manager.
3. В Script собрать небольшой **серверный** тестовый мод, который не требует обновления клиентов.
   Открыть результат сборки → действия с JAR → «Применить на этом сервере…».
4. Папка сервера берётся из панели. Если она ещё не выбрана — выбрать её один раз.
   Обзор показывает добавление/замену и SHA256. Нажать «Применить и перезапустить», подтвердить.
5. Проверить новую версию мода на сервере и сохранность блоков. Если этот клиент был подключён
   к данному локальному серверу, адаптер108/110 должен показать прежнюю обложку и вернуть его.
   Без активного подключения автоматического входа не будет.
6. Собрать версию с ранней ошибкой загрузки мода (до загрузки мира). Применить её так же.
   Сервер должен один раз вернуть прежний JAR и запуститься, панель — сообщить об откате.
7. Сервер → Продвинутые настройки → сохранить отчёт: в ZIP должны быть update115.json,
   журнал неудачного запуска и обычные логи. Не присылать owner74.key и другие ключи.

Это список ручной приёмки, а не заявление, что Minecraft/Windows уже проверены здесь.

## Правила применения

- Локальный владелец папки ОС; сетевой игрок не получает новый APPLY115 через maop/OP.
- Работает только с текущим owner115 capability, текущим run/generation, свободной очередью
  и полным неизменившимся составом mods. Java snapshot проверяется ещё раз процессом владельца.
- Замена по точному полному набору ID в JAR. Частичное замещение multi-mod JAR, повторные ID,
  защищённый Genesis и неоднозначный выбор блокируются. Добавление получает безопасное имя.
- Изменённый код/сборка/зависимости сборки после обзора отменяют применение до остановки.
- Изменённые настройки запуска требуют отдельного обычного рестарта перед применением JAR.
- Только изменённые JAR сохраняются в журнале. Мир/вся папка сервера не копируются.
- Замена происходит после подтверждённого save+stop и освобождения Job/мира.
- Ошибка раннего старта → восстановление прежнего JAR → ровно одна попытка старого запуска.
- Если новый процесс начал загрузку мира, нет слепого запуска старых модов: требуется проверка.
- Живой/зависший/неизвестный Job не считается остановленным из-за таймера. Контроллер остаётся
  с ним до подтверждения остановки; автоматическое принудительное убийство не добавлено.
- Прерывание владельца использует существующий журнал104 и режим проверки восстановления.
- Это не отмена обновления после успешного READY и не гарантия отката произвольного изменения мира.

## Что ещё не подключено

| Система | Состояние |
| --- | --- |
| Локальная сборка → серверная замена115 | Код соединён; нужна ручная приёмка Minecraft/Windows |
| Старый мастер84 → актуальный простой owner104 | Следующий участок интеграции |
| CLIENT/SERVER набор → доставка всем клиентам | Отдельные механизмы есть; полный текущий цикл ещё не завершён |
| Согласие30с, отмена,25%, admission | Нельзя считать завершёнными по локальному тесту115 |
| Полные approved исходные snapshots и флажки | Нет единого обязательного gate всех путей |
| Workspace112, maop113 | Подключены интерфейсы; настоящие multiplayer испытания ещё нужны |
| OT/цветные курсоры/детальные ACL/общие текстуры | Новые функции отложены до завершения имеющихся цепочек |

JAR preflight проверяет структуру, provenance, ID и состав папки, но не заменяет NeoForge
при проверке всех runtime зависимостей/загрузке классов. Клиентские JAR этим действием не меняются.
Для общего мода, требующего одинаковых версий у игроков, нужен следующий парный rollout, а не115.
