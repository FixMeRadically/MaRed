# Подключение, LAN и графическая консоль — изменения 128

Изменения внесены в исходники. Внутренняя версия genesis-core: 0.1.43. Установка на пользовательский сервер не выполнялась.

## Что было проверено отдельно

- Текущий сервер отвечал на Minecraft status по IPv4 и IPv6 на 25565.
- Настоящий клиент NeoForge с отдельным профилем verification/client128 и именем Genesis128 прошёл вход на пользовательский сервер: сервер записал `logged in` и `joined the game`, клиент получил игровые данные. Это отдельная проверка от статуса TCP. Журналы: verification/server59/results128-real-client.log и verification/client128/logs/latest.log. Пользователь прервал дальнейшее управление окном клавишей Escape; тестовый клиент не закрывался принудительно.
- Попытка из старого клиентского журнала на 192.168.1.134:4445 относится к отдельной попытке пользователя через Porthole. Она не используется как объяснение основного сбоя.
- NeoForge уже имеет стандартный LAN pinger. В снимке потоков пользовательского сервера он присутствовал, настройка advertiseDedicatedServerToLan включена. Сам факт работы этого потока не подтверждает доставку multicast до конкретного клиента.
- Контроллер действительно принудительно дописывал nogui при вызове run.bat, хотя в пользовательском BAT этого флага не было. Это отключало графическое окно Minecraft Server.

## Изменения

1. Вызов run.bat больше не дописывает nogui. Если пользователь явно указал nogui внутри собственного BAT, этот выбор сохраняется. Файл BAT не переписывается. Контроль CMD/Java через Windows Job и проверка фактического кода выхода JVM сохранены.
2. Панель локального сервера показывает кнопку «Присоединиться», адрес для этого компьютера и доступные IPv4-адреса локальных интерфейсов для других игроков. Адрес и порт берутся из подписанной текущей сессии запуска, а не из уже изменённых server.properties для будущего запуска.
3. Готовый локальный сервер добавляется в стандартный сохранённый список Multiplayer клиента. Эквивалентные localhost/IPv4/IPv6 записи повторно не создаются, пользовательские записи не удаляются. Подключение идёт через обычный ConnectScreen с существующим bootstrap-перехватчиком; проверка активного обновления не обходится.
4. К стандартному объявлению NeoForge добавлена рассылка на доступных multicast-интерфейсах по IPv4 и IPv6. Это устраняет зависимость дополнительного объявления от одной выбранной системной сетевой карты/IP-семейства. Используются стандартные группы Minecraft/NeoForge и UDP-порт обнаружения 4445; внутри объявления передаётся настоящий игровой TCP-порт. На остановке сервер закрывает все свои multicast-сокеты.
5. Объявление не включается для интегрированного сервера, loopback-only bind или выключенной advertiseDedicatedServerToLan. Дополнение можно отключить свойством genesis.server.lan.disabled=true. Настройки брандмауэра и роутера не меняются.
6. Консоль BAT дополнительно печатает адрес для локального входа и адреса для игроков LAN, если доступны сведения текущей подписанной сессии.

## Как применить

1. Собрать проект обычным `./gradlew build`.
2. Штатно остановить сервер, установить свежий мод на сервер и клиенты. Работающий Java-процесс не подхватывает изменения этих классов автоматически.
3. Полностью запустить сервер заново через обычный run.bat. При отсутствии nogui/headless в пользовательских параметрах должно открыться окно Minecraft Server. Терминал контроллера может оставаться открытым рядом.
4. В клиенте открыть панель Genesis и выбрать ту же папку сервера. После подтверждённой готовности станет доступно «Присоединиться», сервер сохранится в Multiplayer.
5. Для разработки через Gradle использовать `./gradlew runClient`, чтобы запуск брал актуальные скомпилированные классы и ресурсы. Уже запущенный клиент также необходимо перезапустить.

## Как входят другие игроки

- На том же компьютере: 127.0.0.1:25565 при текущем игровом порте 25565.
- В той же локальной сети: адрес компьютера сервера и игровой порт, например 192.168.1.134:25565, если этот адрес по-прежнему назначен компьютеру. Дополнительное LAN-объявление позволяет обнаружить сервер автоматически при доступном multicast.
- Через интернет: внешний адрес с доступным игровым TCP-портом либо конечный адрес туннеля. Автоматический LAN-поиск не обнаруживает произвольные серверы интернета. Пользователь должен настроить доступ выбранным способом; это изменение не открывает порты автоматически.
- На других компьютерах 127.0.0.1 указывает на них самих, поэтому его нельзя передавать друзьям как адрес этого сервера. Клиентам нужны совместимые Minecraft/NeoForge и моды.

Сохранённая запись сервера на хосте не зависит от доставки multicast. Обнаружение между разными устройствами всё ещё зависит от маршрутизации сети, VPN, изоляции Wi-Fi и правил UDP/TCP; проверка на одной машине не является проверкой чужого роутера.

- serverJoinChecks128: 42 проверки адресов, подписанной активной сессии, устаревших и подменённых данных, игрового порта и формата LAN.
- serverLanNetwork128: реально принят multicast-пакет от 192.168.1.134 с игровым портом 25565; работали 4 отправителя по интерфейсам/IP-семействам.
- serverBatchNativeChecks124: реальные CMD/BAT/Java с кодами выхода 0 и 7; отдельный запуск настоящего графического окна Swing из того же Job; процессы завершены, Job пуст.
- serverPythonChecks124: 1075 тестов, ошибок и падений нет, 18 пропусков возможностей окружения. Дополнительно прошли auto106 (47), server105 (85), ресурсы контроллера. Лог: verification/server59/results128-network.log, BUILD SUCCESSFUL, 1 мин 2 с.
- verification/server59/gui_native128.py: отдельный настоящий NeoForge-сервер со свежим миром verification/server128-gui/world128, JDK21 и новым модом. Он дошёл до READY, имел видимое главное окно «Minecraft server» (PID и HWND записаны в verification/server59/gui128-window.json), затем контроллер подтвердил STOPPED_SAVED и пустой Job. Пользовательский сервер и его мир в этом тесте не запускались и не останавливались. Лог: verification/server59/results128-gui.log.
- Заключительный прогон test/serverJoinChecks128/serverSetupResourceChecks59: BUILD SUCCESSFUL; JUnit 277 тестов, ошибок и падений нет. Лог: verification/server59/results128-final.log. Проверки синтаксиса Python/JSON и diff прошли.

Тестовые библиотеки/мир внутри verification/server128-gui оставлены как диагностический стенд. Тестовый сервер остановлен. Готовый мод как отдельный результат пользователю не передавался; сборка JAR выполнялась для проверки упаковки и настоящего запуска.
