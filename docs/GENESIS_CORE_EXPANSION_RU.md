Сборка после UX-02 завершилась за 4:59, а после установки 66 файлов Unified за 4:47. В обоих случаях Gradle вывел `BUILD SUCCESSFUL`. Windows PowerShell подтвердил установку Unified и сохранил резервную копию.

Исключения `fixture unload`, `Expected broken-provider fixture140` и `Expected partial-provider fixture140` относятся к тестам отказа. Строки `FAILED` и `RECOVERY_REQUIRED` внутри заданий контроллера также описывают сценарии тестов. Часть проверок символьных ссылок пропущена: тестовый процесс Windows не смог их создать. Сообщения об устаревших API Java и совместимости с Gradle 9 стоит разбирать отдельно. Успешная сборка подтверждает компиляцию Unified и запуск задач, входящих в `build`. Запуск Minecraft и подключение друзей журнал не показывает.

## Что используется в новой версии

| API Genesis Core | Где MaRed использует реализацию |
| --- | --- |
| `CodeSyntaxLexer.languageFor(path)` и `lex(language, line, state)` | Подсветка в Scripts и обеих реализациях Workspace, выбор шаблона фрагмента и навигация по скобкам |
| `CodeBrackets.pairs(path, lineCount, lines)` | Переход к парной скобке и выделение блока. Адаптер MaRed преобразует позиции в операции над документом |
| `EditorSplitState<K>` | Распределение открытых документов между двумя областями Scripts и выбор активной области |

Сканирование скобок игнорирует строки и комментарии. Если лексер обрезал токены длинной строки, операция останавливается с уже существующим сообщением о лимите. Ранее собственная проверка могла пропустить переполнение, потому что лексер возвращал пустой список. Публичные смещения измеряются в единицах UTF-16, между переданными строками учитывается одна позиция перевода строки.

Для Java 21 из корня MaRed:

```powershell
.\gradlew.bat :genesis-core:publishToMavenLocal
```

В Gradle-проекте, использующем опубликованный локальный артефакт, добавьте `mavenLocal()` и зависимость:

```groovy
implementation 'com.fixmer.genesis:genesis-core:0.1.53'
```

Минимальный пример без API Minecraft:

```java
import java.util.List;
import com.fixmer.genesis.technology.editor.CodeBrackets;

var lines = List.of("run(", "  \"text [\")");
var pairs = CodeBrackets.pairs("Main.java", lines.size(), lines::get);
```

Jar-in-Jar MaRed по-прежнему включает Genesis Core. Сравнение затронутых классов редактора до и после переноса показало 41 210 и 5 623 байта байткода в собственных классах мода. Это выборка классов до сжатия. Нужен замер полного собранного JAR, поскольку часть кода теперь находится во вложенном JAR.

## Что нашлось при статической проверке

- `MaredExprFast.java` не имел вызовов. `MaredExpr` использует `ExpressionEngine` из Genesis Core. Старый альтернативный обработчик исключён из сборки. Старые копии перенесённых файлов тоже исключены, чтобы обновление поверх предыдущей версии не собирало дубликаты.
- `MaredLogFilterPanel.java` не имеет видимых точек входа. Активный `MaredLogPanel` уже обрабатывает фильтры. Подключение отдельной панели продублировало бы фильтры.
- `WorkspacePath129.java` реализует ввод пути и вызов обработчика, но статических вызовов обнаружено не было. Его можно использовать как альтернативу дереву папок, если подключить к нужному действию, проверять путь по правилам текущего Workspace и повторно проверять разрешения на сервере. Маршрут не активирован.
- `MaredLabel.java` можно использовать на новых экранах с экранным диктором после проверки фокуса и озвучивания. Текущие экраны сами рисуют подписи. Массовая замена требует проверки рендера.
- У `ServerPanelScreen66.java` и `SimpleServerScreen103.java` статические вызовы не обнаружены. Подключение старых серверных экранов требует сравнения с действующим серверным интерфейсом и проверок миграции. В серверную логику этим патчем изменений не внесено.
- `MaredClient.java` обнаруживается загрузчиком через `@Mod`. Аналогичные регистрации, миксины, ServiceLoader и внешние потребители библиотечного API нельзя определять по одному числу ссылок.

В CSV перечислены исходники, ресурсы, инструменты, проверки, документация и конфигурация проверенной копии проекта. Для Java указано число других файлов с простым именем типа и число совпадений в текстовых ресурсах регистрации. Это список для поиска кандидатов, поскольку совпадение может быть в комментарии или относиться к одноимённому типу. Для ресурсов и скриптов CSV фиксирует наличие файлов. Запуск всех компонентов отдельно не проверен. В инвентаризацию не входят кэши, встроенные резервные копии, генерируемые файлы и старые автономные тестовые заглушки, отсутствующие в рабочей копии.
