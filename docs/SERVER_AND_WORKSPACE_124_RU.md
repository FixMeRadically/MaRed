Изменения внесены непосредственно в исходники проекта. Для этой работы не выпускаются

## Найденная ошибка BAT

В сохранённых журналах `C:\Users\fixme\Desktop\server\.genesis\server104\logs`
есть `SERVER104_JAVA21`, после которого bootstrap выдаёт `SERVER106_CONTROLLER_START_FAILED`.
Установлены JDK21 и JDK25; стандартный `run.bat` вызывает `java` из PATH, а старый
bootstrap передавал контроллеру именно текущую Java, даже если это Java25.

Кроме того, `inplace104.config()` самостоятельно собирал команду Java с `win_args.txt`.
Содержимое BAT учитывалось только для выбора версии NeoForge, сам BAT не запускался.

Теперь контроллер104 исполняет **реальный `run.bat` выбранной папки** через системный
CMD, с `cwd` этой папки, `JAVA_HOME` и PATH выбранной проверенной Java21. Если исходная
Java не21, проверяются установленные JDK и переменные окружения; новый JDK не скачивается.
Неподходящая Java не заменяется предположением по имени папки: выполняется `java -version`.
Локальный `java.cmd` в корне сервера не подменяет выбранную Java.

Поддержан стандартный BAT NeoForge: комментарии, echo off, переход к `%~dp0`, вызов
`java @user_jvm_args.txt @libraries/.../win_args.txt %*`, pause и exit /b.
Произвольный START/CALL или другой сценарий отклоняется с отдельным объяснением,
вместо попытки угадать эквивалентную команду Java. BAT не переписывается.

CMD и Java находятся в одном новом Windows Job. Реальный тест обнаружил, что PAUSE
сбрасывает код ошибки Java. Контроллер теперь удерживает HANDLE JVM, предварительно
подтвердив её принадлежность своему Job, и отдельно учитывает код JVM и код CMD.
Пропущенная/неоднозначная идентичность JVM не считается успешным выходом. Остановка
и обновление по-прежнему требуют свидетельства сохранения и завершения всего Job.

В локальной панели отображается способ запуска `run.bat`. Владелец процесса остаётся
отдельным от клиента, поэтому запуск BAT не отменяет управление перезапуском и обновлениями.

Пользовательская папка сервера, её BAT, старый bootstrap и установленный мод этой работой
не изменялись. Изменения заработают после твоей сборки и обновления мода. Для обычного
входа через уже установленный bootstrap выбор Java21 выполняется также в новом Python-контроллере,
который извлекается из обновлённого мода; один старый запуск Java25 не заставляет дочерний сервер
работать на Java25.

Общим Workspace можно пользоваться как совместным **текстовым редактором** после обновления
мода у сервера и участников. Полноценным общим окружением разработки с автоматической доставкой
утверждённого кода на сервер его пока считать нельзя. Реальная игровая работа двух клиентов
не проверена этой сессией; API-компиляция, независимые клиентские JVM и проверки хранилища
не подменяют игровой тест.

На выделенном сервере из консоли: `maop <игрок> workspace` либо нужная более широкая роль.
В игре: боковая панель редактора → общий Workspace → создать проект → «Участники» → выдать роль.
Владелец одиночного мира получает право создания через существующую проверку хозяина мира.
Обычный Minecraft OP сам по себе не заменяет Maop.

## Новое в124

- **Недавно удалённые файлы** доступны через «История», даже после закрытия их вкладок.
  Индекс последних4096 исторических путей восстанавливается из журнала; показываются до64
  недавних удалённых файлов с учётом прав. Более старый путь можно ввести в поле пути и открыть
  историю по нему. Журнал остаётся источником восстановления, индекс не удаляет историю.
- **Страницы истории** содержат до64 событий и переход к более ранним версиям. Удалённое
  состояние не предлагается как версия содержимого для восстановления.
- **Обслуживание документа** по подтверждению пересоздаёт служебные CRDT-узлы, сохраняя текст
  и всю историю. Требуются EDIT и RESTORE, поэтому обычный разработчик выполнить его не может.
  Файл получает новую идентичность: старые очереди участников отклоняются и остаются локальными.
  Это ручное обслуживание с предупреждением, а не бесшовная автоматическая компактация.
- **Цвет курсора** задаётся палитрой или шестнадцатеричным RGB и сохраняется локально для UUID
  участника. Ошибка настройки цвета не блокирует редактирование и не выдаёт права.
- Скрытая CODE-панель закрывает также историю и обслуживание соответствующего файла.
- Переименование и удаление ждут отправки текущих правок; структурная операция временно
  блокирует ввод до ответа без сброса фокуса. После переименования открывается новый путь,
  вместо оставшейся заблокированной вкладки со старым именем.
- Исправлены Windows-фикстуры проверок: байты подписанной политики Maop записываются с LF,
  UTF8 читается явно, тестовый CLI не исполняется при импорте. Условия создания symlink
  проверяются отдельно; отсутствие привилегии1314 пропускает только создание фикстуры,
  не подавляет ошибки продукта. Исправлена нормализация legacy classpath на Windows.

Ограничения редактора сохранены:32 проекта,64 файла на проект,8192 code points на текст,
8 клиентских буферов,32768 живых/удалённых узлов документа. Журнал ограничен256MiB/65536
записей; обслуживание документа не очищает журнал. Автоматическая архивация журнала остаётся задачей.
