# MaRed / Genesis — world-startup-07

Следующий этап после lifecycle-06: продолжение шага 10 исходного плана — временный профиль дистанций с постепенным возвращением обычных настроек после входа в мир.

## Что изменилось

В performance-05 профиль держал уменьшенные дистанции до выхода из мира. Теперь он:

1. Перед dev-автооткрытием одиночного мира запоминает исходные значения и применяет начальные caps.
2. Ждёт появления мира и игрока, локального integrated server и отсутствия resource overlay.
3. Выдерживает 2 секунды непрерывной готовности (по умолчанию).
4. Возвращает render/simulation по 2 единицы каждые 500 мс, до исходных значений.
5. Завершает профиль и удаляет recovery-журнал после последнего шага.

После длинной паузы делается только один шаг за клиентский тик; накопленные шаги не выполняются залпом. При временной потере готовности задержка устойчивости начинается заново. Если игрок/мир не готовы непрерывно 120 секунд, профиль снимается, настройки возвращаются; загрузка мира не отменяется.

Сохранение выбора пользователя ведётся по каждой оси отдельно: если во время работы вручную изменить render distance, профиль перестаёт управлять ею, а simulation distance продолжает возвращаться. Выход из мира, штатный restart и отказ открытия возвращают оставшиеся управляемые настройки сразу.

Перед каждым изменением записывается текущий и предыдущий шаг; затем сохраняются options. При прерывании процесса следующий запуск может восстановить настройки с любой стороны этого перехода. Журнал старого формата 05 поддерживается. Повреждённый, пустой или изменённый извне активный журнал не перезаписывается. Защита ручных значений действует по сравниваемым значениям: изменение на точно совпадающее значение нельзя отличить от отсутствия изменения после внезапного завершения процесса.

Профиль по умолчанию **выключен**, как и в 05. В обычном ручном входе в мир он не включается: используются существующие точки prepare() только для dev quickstart/local resume.

## Установка

Применяйте после lifecycle-06. Изменяется только DevWorldProfile.java и добавляется docs/WORLD_STARTUP_07_RU.md; остальные файлы 06 не заменяются. Технически payload совместим также с performance-05, где этот класс тот же, но исправления жизненного цикла supervisor доступны именно в 06.

Закройте игру и supervisor, распакуйте комплект и из его папки выполните:

```powershell
py .\patch\apply_changes.py "$env:USERPROFILE\Desktop\MappetPort\MaRed" --check
py .\patch\apply_changes.py "$env:USERPROFILE\Desktop\MappetPort\MaRed"
```

Либо запустите apply.cmd для стандартного пути. Preflight не меняет проект. Перед записью создаётся бэкап; его точный путь печатается. При неизвестных локальных правках установка отказывается менять файлы.

Затем из MaRed, с JDK 21:

```powershell
.\gradlew.bat clean build
.\gradlew.bat runClient
```

Для отката, при закрытых игре и supervisor, из комплекта:

```powershell
py .\patch\apply_changes.py "C:\путь\к\MaRed" --restore "C:\путь\к\MaRed-supervisor-backup-..."
```

Восстановление сохраняет исходные байты файлов и не перезаписывает последующие локальные изменения.

## Включение

В существующем файле `run/client/config/mared/dev/startup.properties` (для другого gameDir — `config/mared/dev/startup.properties`) задайте или обновите только эти ключи, сохранив остальные настройки:

```properties
fastWorld.enabled=true
fastWorld.viewDistance=4
fastWorld.simulationDistance=4
fastWorld.restoreAfterReadyMs=2000
fastWorld.restoreStepMs=500
fastWorld.restoreStep=2
fastWorld.startupTimeoutMs=120000
```

- caps никогда не поднимают уже меньшие исходные значения;
- restoreAfterReadyMs: 0–30000 мс непрерывной готовности;
- restoreStepMs: 100–10000 мс между шагами;
- restoreStep: 1–8 единиц за шаг;
- startupTimeoutMs: 1000–600000 мс непрерывной неготовности перед отказом от профиля;
- неверные значения отклоняются до изменения опций.

Если профиль уже был включён в 05, новые параметры можно не добавлять: действуют указанные значения по умолчанию. С этим обновлением cap больше не держится всю сессию — исходные дистанции возвращаются автоматически.

При исходных render=12/simulation=10 и caps=4/4, через две секунды устойчивой готовности первый шаг даст 6/6, затем 8/8, 10/10, 12/10 с интервалом 500 мс. Это расписание изменения опций; оно не означает, что чанки уже успели полностью построиться.

Отключение: fastWorld.enabled=false. Для уже активного профиля это действует со следующего prepare; выход из текущего мира немедленно возвращает его управляемые опции.

## Проверка в Minecraft

1. Установите привычные render/simulation distance и запомните их.
2. Включите профиль. Выполните ручной restart из меню MaRed или примените ChatImage, вернитесь в тот же приватный одиночный мир.
3. Проверьте сообщения в latest.log: World startup cap → World distance restore step → World startup profile complete.
4. После завершения профиля проверьте исходные дистанции в настройках; world-profile-restore.properties должен исчезнуть.
5. Для проверки ручного выбора увеличьте restoreAfterReadyMs, во время этой паузы поменяйте одну дистанцию. После возврата другой дистанции ручное значение должно сохраниться.
6. Выйдите из мира до завершения возврата: управляемые значения должны восстановиться сразу.
7. Проверьте отключённый профиль: ручные и dev-входы не должны менять дистанции.

Не удаляйте recovery-журнал вручную во время профиля. Если он повреждён, мод сохраняет его для разбора и не начинает новый профиль поверх него.

## Измерения и границы шага 10

Отчёт из lifecycle-06 остаётся доступен:

```powershell
py .\tools\restart_report.py --html restart-report.html
```

world_ready в нём приходит до завершения постепенного возврата дистанций. Сравнивайте время до появления игрока отдельно от времени восстановления опций и достройки чанков. Время завершения профиля записывается в latest.log от первого наблюдавшего его клиентского тика; это не полный рестарт и не benchmark фоновой генерации чанков.

Изменение опций может вызвать дополнительную работу загрузки и рендера; размер шага и интервал требуют проверки на вашем ПК. Этот патч использует существующие стандартные options. Он **не заменяет ChunkMap, не пропускает spawn preparation, не переносит игровую логику на произвольные фоновые потоки**. Серверные gamerules, forced chunks и сохранения мира не изменяются. Проверка реального эффекта integrated server и сторонних модов остаётся игровой проверкой.

По исходному плану: шаг 10 продвинут, но остаётся частичным. AppCDS для Minecraft и GraalVM native image этим патчем не реализованы.

## Проверки

Проверен production DevWorldProfile, скомпилированный JDK 17 с явно обозначенными Minecraft/NeoForge API doubles: начальные caps, задержка/шаг/интервал, отсутствие catch-up burst, отдельное владение осями, ручной выбор предыдущего значения, прерванная запись шага, старый журнал 05, готовность/overlay, timeout, отрицательное начало монотонных часов, ошибки конфигурации, внешние правки журнала, пустой журнал и отключённый режим. Прежний shutdown adapter проверяется без изменений.

Установщик проверяется на payload 05 (тот же DevWorldProfile, что в 06): preflight/apply/repeat/restore/CRLF/защита локальных правок/откат при сбое записи.

**Полная сборка MaRed с JDK 21, Minecraft и Windows здесь не выполнялась. API doubles не заменяют игровой typecheck и проверку поведения чанков.**
