# Упаковка JAR — исправление 127

Сообщение пользователя: `:jar` не смог добавить `build/resources/main/mared/commands` в `mared-0.4.0.jar`.

Повторные `jar --stacktrace` и `clean jar --stacktrace` до изменения прошли успешно; точная низкоуровневая причина исходного сбоя не воспроизведена.

Устаревший каталог шаблонов `mared/commands` исключён из source resources, processResources и JAR, включая пустую директорию. Убрана задача Delete, которая перед копированием удаляла этот каталог из чужих выходов. Пользовательские команды в `config/mared/commands` это изменение не затрагивает. Исключение на самом JAR также защищает от старых выходных файлов после инкрементальной сборки.

Существующая JUnit-проверка усилена: проверяется отсутствие любых записей этого каталога, включая сам каталог, а не только JSON.

Проверено с JDK 21:

- Полный `clean build --stacktrace --console=plain`: BUILD SUCCESSFUL, 112 задач, 4 мин 57 с. Лог: `verification/server59/results127-clean-build.log`.
- JUnit: 277 тестов, ошибок и падений нет; полный Python-набор: 1074 теста, 18 пропусков окружения, ошибок и падений нет.
- Пробный устаревший JSON создан внутри build/resources/main/mared/commands, затем выполнен повторный jar без clean: BUILD SUCCESSFUL; исключённый файл не делает JAR устаревшим и не попадает в архив. Пробный файл после проверки удалён. Лог: `verification/server59/results127-stale-jar.log`.
- Проверены отсутствие устаревших ZIP-записей, CRC всех записей, основной класс MaRed и вложенный genesis-core 0.1.42.

Обычная команда пользователя остаётся прежней: `./gradlew clean build`. Версия runtime/core в этом исправлении не менялась.
