# MaRed / Genesis — supervisor-lifecycle-06

Применяется **поверх установленного supervisor-performance-05**. Это небольшой следующий патч: жизненный цикл supervisor и отчёт по перезапускам (развитие шага 13).

## Изменения

- Обычный выход из Minecraft завершает supervisor, HTTP-сервер и удержание supervisor.lock. Отдельный controller без игры больше не остаётся.
- `/stop` завершает сессию целиком. Для следующей игры запускайте обычный MaRed; старый controller больше не доступен через `/start`.
- Принятый restart сохраняет controller и запускает один новый клиент. Старый exit watcher не закрывает supervisor после запуска новой игры.
- Выход с ненулевым кодом без активного пробного мода завершает supervisor. Даже custom CDS не вызывает самостоятельный повторный запуск обычной игры.
- Сбой кандидата во время применения мода по-прежнему возвращает прежний JAR и пробует прежнюю установку один раз. Если она тоже падает, supervisor завершается. Обычное закрытие пробной игры возвращает JAR и завершает supervisor без запуска игры.
- Закрытие controller из его lifecycle worker не прерывает и не ожидает сам этот поток. Убрано лишнее пятисекундное ожидание.
- Таймер trial, увидев уже завершённый процесс, оставляет обработку exit watcher: он не должен открыть закрытую пробную игру.
- В timings.jsonl появились cycleId и cycleKind. Остановка старой JVM и запуск новой связываются в один цикл. Повторные milestone-метки не удваиваются; world_load вычисляется и при обратном порядке доставки меток.
- Новый `tools/restart_report.py`: таблицы по этапам, медиана/P95/N, отдельные initial/restart/rollback, история последних циклов и сравнение с базой. Читает текущий и previous журналы. HTML автономный, работает без сети.

Изменяется только три Java-файла supervisor; DevActivationService, редактор, импорт и настройки подключения этот патч не заменяет. Незнакомые локальные изменения в затронутых файлах установщик сохраняет отказом от установки; бэкап создаётся перед записью.

## Установка

1. Закройте Minecraft и оставшийся старый supervisor перед обновлением. Старый процесс сам новую логику не получит.
2. Распакуйте комплект. Из его папки:

```powershell
py .\patch\apply_changes.py "$env:USERPROFILE\Desktop\MappetPort\MaRed" --check
py .\patch\apply_changes.py "$env:USERPROFILE\Desktop\MappetPort\MaRed"
```

Либо запустите `apply.cmd` для стандартного пути. Если preflight пишет `Base differs`, файлы не изменены: не обходите проверку и не переписывайте их вручную.

3. Из проекта MaRed, с JDK 21:

```powershell
cd "$env:USERPROFILE\Desktop\MappetPort\MaRed"
.\gradlew.bat --stop
.\gradlew.bat clean build
.\gradlew.bat runClient
```

Установщик печатает точный каталог резервной копии. Для отката, после закрытия игры и controller:

```powershell
py .\patch\apply_changes.py "C:\путь\к\MaRed" --restore "C:\путь\к\MaRed-supervisor-backup-..."
```

Команда выполняется из комплекта. Откат откажется перезаписывать файлы, изменённые после установки.

## Проверка в игре

1. В приватном одиночном мире примените исправленный ChatImage как раньше. После перезапуска проверьте `/sendimage SGVsbG8=`.
2. Выполните ещё один ручной restart из меню MaRed. Должен вернуться один клиент с прежним миром/позицией.
3. Полностью закройте игру её обычной кнопкой. После завершения дочернего launcher/Gradle-процесса supervisor должен исчезнуть. В журнале controller: `Game session ended; closing supervisor and releasing control port`.
4. Порт можно проверить без завершения каких-либо процессов:

```powershell
Get-NetTCPConnection -LocalPort 27670 -State Listen -ErrorAction SilentlyContinue
```

При стандартном порте и отсутствии других приложений вывода не будет. Если выбран другой порт, проверяйте его.

5. Снова запустите MaRed и примените мод: запуск controller не должен конфликтовать с предыдущей сессией.
6. Закройте пробную игру до входа в мир. JAR должен откатиться, игра сама не открывается. В `config/mared/dev/deployments/last-result.properties` — ROLLED_BACK.

Если запуск идёт через Gradle, supervisor наблюдает процесс launcher и его известное дерево. Между исчезновением окна игры и выходом launcher может быть задержка. Произвольные отсоединённые процессы сторонних launcher здесь не решены.

## Отчёт о времени

После нескольких одинаковых перезапусков одного мира, из папки проекта MaRed:

```powershell
py .\tools\restart_report.py --html restart-report.html
```

Откройте `restart-report.html` в браузере. По умолчанию скрипт ищет logs в текущей папке, `config/mared/dev/logs` и `run/client/config/mared/dev/logs`. Другой gameDir или один журнал задаётся явно:

```powershell
py .\tools\restart_report.py "C:\Minecraft\config\mared\dev\logs" --html restart-report.html
```

Для сравнения сохраните журналы контрольной серии **до** эксперимента в отдельную папку, измените один параметр (например warmCache.enabled), затем выполните:

```powershell
py .\tools\restart_report.py --compare "C:\measurements\baseline" --html restart-report.html
```

В baseline должны лежать timings.jsonl и, если он был, timings.previous.jsonl. Сравнивайте тот же мир, JDK, моды, команду и профиль дистанций; не смешивайте холодный запуск с прогретым. Контрольная выборка не вычитается из текущего журнала автоматически: для независимых серий используйте разные файлы/папки. Скрипт не меняет журналы.

«От запроса до готового мира» — монотонное время supervisor от принятия restart до получения world_ready. Предварительные build и сохранение мира сюда не входят. prepare может перекрываться с shutdown; world_load входит в общий возврат. Строки не складываются. world_ready означает появление мира/игрока, а не завершение отрисовки всех чанков.

Журналы 05 отображаются отдельно без выдуманного связывания shutdown и запуска. Новый cycleId появляется только у обновлённого controller. Частичные циклы видны в истории, но не входят в общий возврат. У каждой строки свой N; на малой выборке P95 нестабилен.

## Выполненные проверки и ограничения

JDK-only supervisor проверяется настоящими дочерними JVM: restart/coalescing, чистый выход/сбой, custom CDS без самопроизвольного повторного запуска, освобождение порта/конфиг-lock, /stop, trial rollback/confirm и отказ второго восстановления. Проверки deployment и отчёта, установка/repeat/CRLF/restore/защита локальных правок приложены в verification.

На этом хосте JDK 17. Полная Gradle-сборка MaRed с JDK 21, Minecraft и Windows здесь не выполнялись. Успешный handoff и наблюдение descendants пропускаются там, где хост скрывает ProcessHandle metadata; это отражено в логах. Независимые проверки не подтверждают скорость Minecraft.
