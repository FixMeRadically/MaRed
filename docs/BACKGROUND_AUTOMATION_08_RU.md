# MaRed / Genesis — background-automation-08

Крупный накопительный патч поверх supervisor-performance-05, supervisor-lifecycle-06 или world-startup-07. Он включает изменения 06/07 и добавляет фоновую автосборку и применение одного выбранного импортированного Gradle-мода без открытого редактора.

## Что входит в этот этап

- Фоновое наблюдение за сохранёнными исходниками при игре в приватном одиночном мире.
- Постоянный выбор одного проекта, пауза/продолжение, выключение и однократная повторная попытка.
- Отпечаток последней попытки сохраняется до запуска build. Ошибка сборки или откат не создают цикл повторных рестартов.
- Изменения, сделанные между игровыми JVM или пока игра была закрыта, обнаруживаются при следующем наблюдении.
- Подготовка настроек, чтение черновиков и вычисление отпечатков выполняются в I/O очереди; Minecraft API и переходы этапов — на клиентском потоке.
- Используется прежний путь build → проверка единственного mod JAR → provenance-checked staging → сохранение мира/игрока → restart → пробный запуск/подтверждение/откат.
- Новая автоматическая попытка ждёт подтверждения предыдущего пробного мода, сохраняя ожидающие изменения.
- Изменение входов во время build отменяет применение результата. Следующее стабильное состояние вызывает новую сборку.
- Смена мира/игрока во время операции отменяет её и ставит автоматику на паузу. На LAN/внешнем сервере фоновое применение не запускается.
- Открытие редактора имеет приоритет: фоновая операция отменяется. Возобновление ждёт завершения записи recovery/workspace после закрытия редактора.
- Несохранённые recovery-черновики блокируют применение и ставят режим на паузу. При закрытии редактора передаются также известные грязные проекты, даже если исходный файл удалён извне.
- Ошибка сохранения состояния редактора блокирует автоматический restart.
- Ручное применение выбранного проекта тоже учитывается как попытка: после его рестарта те же входы автоматически не применяются второй раз.
- Статус, ограниченный журнал с хвостом Gradle-вывода и управление доступны из меню и клиентских команд. Добавлены русские и английские подписи.
- В комплект включены 06: завершение supervisor вместе с обычной игрой и отчёт замеров; 07: постепенный возврат дистанций после dev-входа.

## Установка

Закрой Minecraft и старый supervisor. Распакуй комплект и из его папки:

```powershell
py .\patch\apply_changes.py "$env:USERPROFILE\Desktop\MappetPort\MaRed" --check
py .\patch\apply_changes.py "$env:USERPROFILE\Desktop\MappetPort\MaRed"
```

Либо apply.cmd для стандартного пути. Уже установленные 06/07 пропускаются; дополнительные ручные изменения в затронутых файлах блокируют установку целиком. Бэкап создаётся до записи, его путь печатается. DevActivationService и твои файлы подключения этот патч не заменяет.

Затем из MaRed с JDK 21:

```powershell
.\gradlew.bat --stop
.\gradlew.bat clean build
.\gradlew.bat runClient
```

Повторная установка ничего не переписывает. Для отката, при закрытых игре и supervisor, из комплекта:

```powershell
py .\patch\apply_changes.py "C:\путь\к\MaRed" --restore "C:\путь\к\MaRed-supervisor-backup-..."
```

Откат отказывается перезаписывать файлы с последующими правками.

## Как включить фоновые сборки

1. Открой MaRed → Scripts и выбери рабочий импортированный Gradle-проект, например исправленный ChatImage.
2. Сохрани или разреши черновики. Желательно сначала подтвердить успешное ручное применение этого проекта.
3. В меню запуска включи «Фоновая сборка выбранного проекта: ВЫКЛ».
4. Полностью закрой окно MaRed/редактор, а не только переключи вкладку. Останься в приватном одиночном мире.
5. После начала наблюдения сохрани изменение исходника в IDE. Для Link редактируй связанную папку; для Copy — рабочую копию MaRed, а не исходную импортированную папку.
6. После нескольких сканов стабильное изменение вызовет build и один restart. Проверь новую версию через `/sendimage SGVsbG8=` и изменённый текст ChatImage.

При первом включении текущее состояние служит исходной точкой — оно само по себе не вызывает build. Для немедленного запуска используй retry. Следующие запуски сравниваются с сохранённой последней попыткой, поэтому изменения между JVM не теряются. Наблюдение начинает работать, когда есть подходящий мир и закрыт редактор.

Старый переключатель «Автосборка и применение» относится к watcher в открытом редакторе. Новый фоновый переключатель отдельный. Они могут быть включены одновременно, но фоновая операция уступает открытому редактору. Одновременно выбран только один фоновый проект: включение другого заменяет выбор.

## Команды во время игры

Это локальные клиентские команды:

```mcfunction
/mared dev auto status
/mared dev auto log
/mared dev auto pause
/mared dev auto resume
/mared dev auto retry
/mared dev auto stop
```

- status — текущий этап и выбранный проект.
- log — краткий хвост журнала в чате. Полный ограниченный журнал есть в меню «Фоновая сборка: статус и журнал», а вывод также попадает в latest.log.
- pause — приостанавливает наблюдение и отменяет текущую непринятую операцию.
- resume — снимает паузу. Прерванная операция будет попробована заново один раз, если она была записана как ожидающая. После обычной ошибки сборки сама resume не повторяет неизменённые входы.
- retry — однократная повторная попытка для текущих входов, даже если их отпечаток уже был обработан. Требуется включённый выбранный проект.
- stop — выключает фоновые сборки и сохраняет это состояние. Для включения снова используй переключатель выбранного проекта в редакторе.

Из меню доступны те же pause/resume/retry/stop. Для проверки текущей сборки удобнее команды: открытие редактора отменяет фоновую операцию, отдавая тебе ручное управление.

Если рестарт уже принят, pause/stop отключают будущую автоматику, но уже принятый рестарт завершается. Подготовленный JAR сохраняется для нового запуска. До принятия рестарта отмена снимает staging; поздно завершившееся сохранение мира не должно запускать отменённую операцию.

## Ошибки и ожидающие изменения

- Ошибка Java/Gradle: JAR не применяется. Сохрани исправление либо вызови retry. Неизменённая ошибка не собирается по кругу.
- Ошибка JDK/Wrapper/dependencies: проверь настройки инструментов в редакторе, затем retry.
- Несколько mod JAR: автоматика не угадывает нужный. Выполни ручную сборку и выбери артефакт.
- Исходники изменились во время build: результат отклоняется; следующее стабильное состояние будет собрано.
- Несохранённые черновики: открой редактор, разреши их, закрой его и вызови resume. Внешнее сохранение диска не должно автоматически перезаписать черновик.
- Ошибка checkpoint редактора: проверь журнал и сохранность документов, затем явно возобнови режим.
- Смена мира/игрока во время операции: режим ставится на паузу, JAR не переносится в другой мир этой операцией. Для продолжения явно вызови resume.
- Завершение/сбой JVM во время build: сохранённый отпечаток не вызывает автоматическую повторную попытку. Для повторения без новых исходников есть retry.

Это наблюдение за исходниками внутри работающего клиента, а не Windows-служба и не глобальный watcher файлов `.class`. Пока игра полностью закрыта, компилятор не работает. Сохранённый отпечаток позволяет обнаружить накопившиеся изменения при следующем входе. Систему фактической доставки JAR и проверки provenance патч использует из твоего существующего core.

## Данные и ограничения

Настройки режима и последний результат: `<gameDir>/config/mared/dev/automation.properties`. Хранится только один root/id, enabled/paused/retry и отпечаток последней попытки. Текущий controller не требует нового протокола: остаётся 4. Не редактируй файл во время работы; неверный/повреждённый файл сохраняется и блокирует автоматические операции, причина отображается в статусе.

Журнал обновляется через временный файл с flush и replace, при межпроцессной блокировке. Claim записывается до начала build, а дубли одного отпечатка отклоняются. Это не блокирует ручной запуск того же внешнего Gradle-проекта из другой IDE: не запускай параллельные сборки в одной рабочей папке. Проверка входов и provenance отбрасывает изменившиеся результаты, но не заменяет согласование сторонних процессов.

Сохранность черновиков проверяется через существующий recovery API для текущих файлов и сведения закрываемого редактора. Резкое прекращение процесса может оборвать незавершённую запись, как и раньше; журнал не является бэкапом исходников/мира. Автоматика не удаляет файлы мира, session.lock или пользовательские Gradle-кэши.

## Проверка на твоём ПК

1. Чистая сборка MaRed и прежний ручной ChatImage edit/apply/export.
2. Link: включить фон, закрыть MaRed, сохранить один текст в IDE → один build/restart, новый текст в `/sendimage`.
3. То же для рабочей Copy-папки.
4. Ошибка Java → нет установки/рестарта/повторов; исправление → один цикл.
5. Два быстрых последовательных сохранения и изменение во время долгой сборки: устаревший результат не применяется.
6. pause во время build, затем resume; stop сохраняется после следующего запуска.
7. Открытие редактора во время build, несохранённый черновик и последующее закрытие: фон уступает редактору и не перезаписывает черновики.
8. Смена мира во время build → пауза, без применения в новом мире.
9. Отказ/отмена restart → staging отменён; успешный restart → кандидат установлен и подтверждён прежним world-ready механизмом.
10. Обычное закрытие игры завершает supervisor; ручной restart остаётся в меню без F9. Профиль дистанций и `tools/restart_report.py` из 06/07 остаются доступны.

## Состояние исходного плана

11 значительно продвинут: фоновый source watcher без редактора, сохранение выбора/попыток между JVM, очередь актуальных изменений и управление. Самостоятельной OS-службы или `.class` watcher нет.

6 и 13 включают исправления 06; 10 включает постепенный профиль 07 и остаётся частичным. 12/14 сохраняются. Реальный охват Minecraft/NeoForge через AppCDS, глубокая переделка ChunkMap/spawn preparation и GraalVM native image здесь не объявляются реализованными.

## Что проверено здесь

Production journal работает на настоящих временных файлах: сохранение/claim/ошибка/повтор/пауза/выключение/переключение/блокировка/защита внешних изменений. Production watcher и клиентский координатор скомпилированы и проверены с явно обозначенными doubles Minecraft, Gradle runner, source storage, input hashing, provenance/staging и restart. Проверены успешный цикл и отмены, stale inputs, черновики, checkpoint failure, downtime, неоднозначные JAR, ошибка инструментов, private-world gate и принятие рестарта без следующего клиентского тика. Команды typechecked с Brigadier doubles; редактор проходит Java parsing, который не заменяет его полный typecheck.

В комплекте также проверки 06/07 и накопительного установщика. Логи лежат в verification. Полная сборка MaRed с JDK 21, настоящий Gradle build импортированного мода, Minecraft/Windows и реальная скорость здесь не проверены: доступен JDK 17 и payload прежних патчей, а не полный репозиторий со всеми зависимостями.
