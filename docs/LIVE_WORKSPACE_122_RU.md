# Genesis122 — подключение совместного текстового Workspace

Установка поверх121 или121 с исправлением bootstrap. Само исправление bootstrap включено. Это новая игровая точка входа на боковой панели редактора. Старый редактор доступен через «Старые проекты».

## Доступно в игре

Создание и выбор серверного проекта; создание текстовых файлов; до8 открытых буферов; две панели с отдельными документами; автоматическая отправка изменений после паузы350ms; чужие цветные курсоры/выделения и список активных файлов. Во время ожидания подтверждения отправленного пакета этот буфер временно не принимает ввод. Это первая рабочая схема синхронизации, не обещание нулевой задержки.

Автор правки — UUID действительного ServerPlayer, сообщённый по текущему соединению. UUID из запуска VSCode не принимается как серверная личность. OP не даёт право создания Workspace: проверяется Maop WORKSPACE_CREATE. Права проекта независимы от Maop: владелец через «Участники» выбирает онлайн-игрока, роль и ограничения папки. Сервер проверяет права на каждой операции.

Локальный черновик и очередь точных CRDT-операций записываются перед отправкой; повтор потерянного ответа не дублирует вставку. Файл после удаления/восстановления имеет новую идентичность: старая очередь не накладывается на него автоматически. Есть действия копирования всего текста, получения серверной версии, закрытия файла, переименования, подтверждения удаления, просмотра и восстановления истории.

«Изменения» позволяет выбрать файлы, проверить хеш набора и утвердить его. Невыбранные изменения остаются черновиками. «Подготовить сборку» сохраняет на сервере точный утверждённый набор в world/genesis/workspaces122/<project>/exports/<hash>. Проверяются файлы, манифест и отсутствие посторонних файлов. Изменение прав отменяет старое разрешение сборки.

## Перенос112

«Старые проекты» показывает прежний редактор и перенос проектов, владельцем которых является игрок. До замораживания проверяется свободное назначение. Исходник не удаляется: он становится read-only. Частичный перенос можно повторить, имеющиеся файлы новой копии сверяются, а не перезаписываются. Поддерживается до64 текстовых файлов, каждый до8192 code points, суммарно до100000; неподходящий источник отклоняется до замораживания. Если диск/процесс оборвал перенос после замораживания, повтори перенос того же проекта; не редактируй файлы журнала вручную.

## Что пока не подключено

Запуск Gradle, доставка артефакта в BuildSnapshot84, публикация и применение через supervisor120. Кнопка подготовки НЕ выполняет код проекта на сервере. Также остаются загрузка полного локального NeoForge-проекта/бинарных ресурсов, расширенный интерфейс отдельных capabilities, сохранение произвольного RGB между сессиями и согласованная компактация tombstone. Авторство фрагментов имеется в backend121, но отдельная панель авторства здесь не добавлена.

## Ограничения

Сервер и все участники нового редактора должны загрузить122. До32 проектов,64 файлов в проекте,8192 видимых code points и32768 узлов в живом документе; восемь клиентских буферов. История не очищается автоматически: журнал ограничен256MiB/65536 записей и размером состояния8MiB. Новые записи сжаты, старые читаются; история распаковывается по запросу. Лимит останавливает запись с ошибкой, а не удаляет историю. Миграция/ручное восстановление требуют подходящего доступного места.

Кэш привязан к серверному fingerprint хранилища, UUID участника, проекту и пути. При изменении личности/хранилища отправка останавливается. Если сохранение кэша не удалось, интерфейс сообщает CACHE_ERROR: скопируй черновик перед выходом. Отзыв прав не может стереть уже прочитанные локальные копии.

## Проверки и первый запуск

Здесь использован JDK17. Проверены настоящие файлы, журналы, подписи разрешений и независимые JVM клиентов, а не Minecraft. Клиентские/серверные адаптеры проверены по API-заголовкам; это НЕ полная сборка NeoForge21.1.264 и НЕ игровой запуск на Windows.

После установки: `gradlew.bat :genesis-core:jar build`. Обнови мод у сервера и клиентов, перезапусти оба. Открой Workspace на боковой панели, создай проект и файл, выдай второму игроку роль «Разработчик». Проверь одновременные вставки, две панели, выход/возврат, отзыв прав и историю. При ошибке сначала сохрани полный текст через «Действия → Скопировать весь черновик», затем приложи client/server latest.log. Приватные lease/key-файлы присылать не нужно.
