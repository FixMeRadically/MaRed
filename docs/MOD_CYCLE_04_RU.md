# Обычный мод: импорт → правки → применение → проверка → JAR

История предыдущего этапа. Текущие изменения протокола/остановки/автоматики описаны в [PERFORMANCE_05_RU.md](PERFORMANCE_05_RU.md).

Этот этап добавляет постоянную установку обычного NeoForge-мода через supervisor. Это отличается от ServerModule: @Mod, регистрация событий, пакеты и клиентский код загружаются штатным NeoForge при старте новой JVM. Повторное применение заменяет один управляемый JAR. Dedicated/LAN оставлены на следующий этап; следующие оптимизации большого плана не добавлялись.

## Проверка в игре

1. Один раз примените патч к MaRed, выполните `gradlew.bat clean build` под полным JDK 21 и запустите обновлённый MaRed. Старый supervisor должен быть закрыт. При обычной установке замените прежний MaRed JAR результатом сборки; `source/MaRed` содержит весь проект, а `patch` — изменения к вашему проекту.
2. Распакуйте `examples/ChatImage` в отдельную обычную папку. В MaRed → Scripts → Проект импортируйте Minecraft/Gradle-проект из этой папки. Copy хранит отдельную рабочую копию; Link связывает редактор с этой папкой. В обоих случаях выбранный корень должен содержать `build.gradle` и `settings.gradle`.
3. В «Запуск → JDK» укажите корень полного JDK 21, например `C:\Program Files\Java\jdk-21`, а не `bin`/`java.exe`. «Проверить инструменты сборки» должен пройти успешно. Используется Wrapper проекта. Первая сборка может долго скачивать Gradle и зависимости; смотрите лог, настройте таймаут при необходимости.
4. Находясь в приватном одиночном мире (без «Открыть для сети»), измените Java/ресурсы через редактор. Нажмите «Запуск → Собрать и применить мод». Можно выбрать этот режим в меню рядом с основной кнопкой запуска. Сохранение выбранного проекта выполняется автоматически, затем запускается именно задача `build`, независимо от настроенной задачи обычной сборки.
5. Пока идёт сохранение/сборка/подготовка, редактор блокирует правки. Ошибка показывается в журнале/отчёте сборки; Minecraft продолжает работать с прежней версией. Исправьте ошибку и нажмите снова. При нескольких mod JAR откройте меню артефактов и выберите «Применить этот JAR в игре» у нужного артефакта; sources/javadoc/runtime-модуль для этого не подходят.
6. После успешной проверки MaRed сохраняет состояние, автоматически включает dev mode и инициирует нормальное закрытие клиента. Supervisor ждёт выхода прежнего процесса, заменяет JAR, запускает Minecraft и возвращает в тот же мир. В одиночной игре вместе с клиентом перезапускается встроенный сервер. Это полный перезапуск игры между версиями; замены классов на лету нет.
7. Для примера выполните `/sendimage SGVsbG8=`. Он выводит уведомление о доставленных данных. Измените текст `sent image data` в `ImagePayloadHandler.java`, примените снова и повторите команду. После перезапуска новая версия остаётся установленной, повторно применять её для активации не нужно.
8. «Запуск → Статус сервера» показывает установленную проверенную версию и последнюю транзакцию. «Экспортировать проверенный JAR» создаёт обычный JAR в `<gameDir>/mared/exports/mod-export-.../` и копирует полный путь в буфер. Это последняя подтверждённая установленная версия, даже если исходники уже изменены или новая сборка упала. Экспорт проекта — отдельная команда для ZIP исходников. Обычная выдача артефакта сборки также сохранена.

## Что проверяется до выхода из игры

Успешный `build`; один выбранный упакованный NeoForge javafml-мод; неизменившиеся исходники и артефакт (SHA-256 и отпечаток входов сборки); буквальные modId/version; необходимые зависимости и совместимость с уже запущенными Minecraft/NeoForge. Требуемые зависимости автоматически не устанавливаются. При несовместимом исходном ChatImage с NeoForge 21.1.259 текущий MaRed на 21.1.235 откажет; пример в архиве согласован с 21.1.235.

Копия кандидата и журнал подготавливаются отдельно. Действующий `mods` не изменяется во время сборки/редактирования. Неизвестный мод с тем же ID, подмена управляемого JAR, другой проект-владелец ID и изменение ID уже установленного проекта блокируют замену. MaRed и системные mod ID нельзя заменить этой командой. Устаревшее намерение старше 30 минут отбрасывается без установки. Stop/закрытие редактора до принятого рестарта отменяют ещё не применённую подготовку.

## Пробный запуск и восстановление

Supervisor устанавливает JAR только после остановки принадлежащего ему дерева процессов. Сохраняет предыдущие байты, журнал фаз и одноразовый маршрут возврата в мир. Новый клиент получает отдельный trial token. Когда клиентский тик видит игрока и одиночный мир, он посылает аутентифицированное подтверждение; supervisor записывает новую версию в каталог. Только после этого доступен её «Экспорт проверенного JAR».

Если дочерний процесс завершился с ненулевым кодом до подтверждения, supervisor возвращает старый JAR (при первой установке удаляет только своего кандидата), восстанавливает маршрут и один раз запускает прежнюю установку. Бесконечного crash loop нет. При отсутствии подтверждения пять минут выполняется остановка/откат и один запуск прежней версии. После прерывания самого supervisor незавершённый trial откатывается перед очередным запуском. Обычное закрытие пробной игры с кодом 0 не запускает её снова само; неподтверждённая версия восстановится при следующем запуске через supervisor.

Откат относится **только к управляемому JAR**. Он не отменяет уже выполненные изменения мира/данных и не гарантирует восстановление от зависания всего компьютера или повреждения диска. Успешная компиляция и открытие мира не доказывают отсутствие ошибок поведения позже. Для испытания модов с изменением блоков/предметов используйте отдельный тестовый мир: удаление такого мода может изменить сохранение. После подтверждения автоматического отката от более позднего игрового сбоя нет. Одна предыдущая версия JAR сохраняется в backups, но это не backup мира.

## Местоположение компонентов

| Компонент | Назначение |
|---|---|
| `com.fixmer.mared.technology.minecraft.NativeModWorkflow` | Связь редактора с проверенным результатом сборки, staging, выдача проверенного JAR |
| `com.fixmer.mared.technology.scripts.ScriptProjectEditor` | Сохранение, build, диагностика, применение и checkpoint перед рестартом |
| `com.fixmer.genesis.technology.scripts.SourceProjects` в `technologies/core` | Copy/Link, исходники и проверенная выдача результата; исправлен путь артефакта Link |
| `com.fixmer.genesis.supervisor.ModJarMetadata` | JDK-only проверка metadata/зависимостей, без загрузки кода проекта |
| `com.fixmer.genesis.supervisor.ModDeployment` | Файловая блокировка, журналы, staging/install/confirm/rollback/export |
| `com.fixmer.genesis.supervisor.Supervisor` | Последовательная остановка/запуск, trial timeout и восстановление |
| `com.fixmer.mared.dev.client.DevModTrial` | Подтверждение пробной версии после входа в одиночный мир |
| Остальные `com.fixmer.mared.dev.*` | Автоактивация, bootstrap, сохранение игрока/мира и возврат; карта в SUPERVISOR_STABLE_03_RU.md |

Runtime-пути отсчитываются от **настоящего каталога игры**, а не Gradle-проекта. `gameDir` теперь явно записывается в supervisor.properties; `workDir` остаётся каталогом команды запуска.

- `<gameDir>/mods/mared-dev-<modId>.jar` — единственная управляемая текущая копия этого мода.
- `<gameDir>/config/mared/dev/deployments/` — lock, pending/trial/catalog/last-result properties, transactions и backups.
- `<gameDir>/config/mared/dev/logs/` — журнал supervisor/дочернего процесса/bootstrap.
- `<gameDir>/mared/exports/` — отдельные выданные проверенные JAR.

Протокол supervisor этого этапа — **3**. Старый supervisor необходимо остановить; мод отказывается готовить обычный мод под старым supervisor. Bootstrap JAR по-прежнему встроен в сборку MaRed; отдельного supervisor Gradle-проекта нет. Внешний launcher, который намеренно запрещает отдельный повторный запуск, может потребовать ручной команды в supervisor.properties; проверяйте bootstrap.log.

## Ограничения первой реализации

Поддерживается обычный NeoForge javafml JAR с одним буквальным modId и version. Сложные TOML-выражения, набор нескольких модов в одном JAR и сложные/квалифицированные диапазоны версий не принимаются. Для зависимостей поддерживаются числовые release-версии, `[v]`, `[a,b)`, `[a,)` и подобные простые диапазоны; это предварительная проверка, окончательную загрузку делает NeoForge. Встроенные JarJar-библиотеки анализируются существующим проверяющим кодом, но полная совместимость произвольных nested mods заранее не доказывается. Встроенные библиотеки, mixins и нативные компоненты всё равно могут дать ошибку при запуске.

Поддержка находится внутри обычного `mods`-каталога, не заменяет моды из IDE classpath/других источников и не переустанавливает сам MaRed. Уже установленный вручную ChatImage следует убрать из внешних источников при закрытой игре перед первым применением через MaRed. Не копируйте рядом экспортированный JAR с тем же ID. Чужие файлы не удаляются автоматически.

`ServerModule` для неимпортированных Java-проектов остаётся прежним механизмом в памяти. Он не превращается в обычный мод и не получает постоянной установки. Этот этап решает цикл для импортированного NeoForge-проекта.

## Состояние проверок

JDK-only supervisor и весь независимый `genesis-core` компилировались на доступном JDK 17. Проверены реальные файлы и дочерние JVM: staging, hashes, подтверждение, откат, восстановление журналов, отмена, экспорт, Copy/Link и отказ устаревшей сборки. Игровой адаптер проверялся с явно обозначенными API doubles; 517 исходников MaRed проходят Java parser. Это **не полная компиляция** MaRed с NeoForge.

Полного JDK 21/NeoForge runtime на этом хосте нет: `gradlew clean build`, реальная сборка ChatImage, Minecraft UI, Windows/handoff/tree здесь не проверены. Для проверки в игре выполните шаги выше на вашем ПК. Никаких обещаний конкретного времени старта или многолетней работы без обслуживания этот этап не делает.
