# Инструменты общего проекта — изменения 126

Код изменён непосредственно в проекте. Архив патча и готовый мод не выпускаются. Внутренний genesis-core обновлён до 0.1.42.

## Новые возможности

### Заготовка NeoForge-мода в общем Workspace

Откройте общий проект, затем кнопку **«Проект»**. Введите ID мода и нажмите **«Заготовка мода»**. Сервер добавит текстовые файлы из уже включённого в MaRed официального MDK: настройки Gradle, исходники примера, конфигурацию, metadata-шаблон и ресурсы. Для этой заготовки выбран NeoForge 21.1.264, соответствующий текущему проекту MaRed.

Операция атомарна: конфликт любого имени, устаревшая ревизия или отсутствие прав отменяет всё добавление. Существующие файлы не заменяются. Изменение записывается одной транзакцией журнала, доступно в истории и не попадает автоматически в утверждённый релиз.

Заготовка предназначена для общего текстового проекта. Скрытые файлы Git, shell-launchers и бинарный Gradle Wrapper в неё не добавляются. Для сборки используется отдельный инструмент на клиенте.

### Импорт локальной папки

В инструментах проекта нажмите **«Выбрать папку»**. Чтение выполняется в фоне. Затем доступны список найденных текстовых файлов, число символов, просмотр содержимого по нажатию на файл и список пропущенных элементов. Отправка на сервер происходит только после **«Импортировать»** и подтверждения.

Импорт переносит снимок прочитанного содержимого. Последующие изменения локальных файлов не подмешиваются в него; для них нужно заново выбрать папку. На сервер передаются относительные пути и текст, без абсолютного пути локального каталога.

Поддерживаются Java, Gradle/Kotlin DSL, JSON, TOML, properties, mcmeta, текст, Markdown, XML, CSV, YAML, cfg и lang. Каталоги build/out/run/runs/target/node_modules/world/logs/crash-reports и скрытые каталоги пропускаются; ссылки и бинарные файлы не импортируются. Неверный UTF-8 и превышение лимита в выбранном текстовом файле останавливают подготовку.

Импорт создаёт только новые файлы. При конфликте хотя бы одного пути сервер не создаёт остальные файлы этой операции. Проверяются права CREATE/READ и видимость CODE для каждого пути, а также общая ревизия. Если другой участник успел изменить проект, нажмите **«Обновить состояние»**, затем повторите импорт. Потерянный ответ на изменение не вызывает слепой повтор: при UNKNOWN обновите состояние и проверьте список файлов.

Текущие пределы: 64 файла на весь проект, 8192 кодовых точки на документ, сжатая посылка до 20000 байт и распаковка до 2 МиБ с ограничением числа файлов. Сканирование ограничено 4096 элементами и глубиной 24. В списке пропусков сохраняются первые 128 элементов. Очень большой или плохо сжимаемый проект нужно переносить частями. Общий лимит состояния и журнала Workspace сохраняется.

### Поиск по общему проекту

В окне **«Проект»** введите текст и нажмите **«Найти»**. Поиск буквальный, с переключателем учёта регистра. Он выполняется на сервере по сохранённым общим текстовым документам, учитывает права READ и видимость CODE. Скрытые файлы и их строки не выдаются.

Результат содержит путь, номер строки и фрагмент текста. Нажатие открывает документ, переводит курсор к найденной строке и прокручивает редактор. Выдача ограничена первыми 100 совпадениями; при превышении предлагается уточнить запрос. Другие участники могут продолжать редактирование, поэтому номер строки относится к моменту поиска.

### Сравнение перед утверждением

В списке изменений рядом с файлом появилась кнопка **«Сравнить»**. Она показывает удалённые, добавленные и неизменившиеся строки относительно утверждённого релиза, с номерами строк и ревизией ответа. Удаления подсвечиваются красным, добавления зелёным.

Просмотр требует VIEW_HISTORY и доступных панелей CODE/RELEASES. Для бинарных данных показывается отсутствие текстового сравнения. Для больших списков строк вместо дорогого полного diff показываются явно отмеченные сокращённые начала прежнего и текущего текста. Просмотр не утверждает файлы: остаются прежние предварительный просмотр точного хеша, подтверждение и проверка ревизии.

### Встроенный Gradle Wrapper

На экране **«Собрать / публикация»** поле Wrapper теперь можно оставить пустым. Клиент использует включённые в мод Wrapper и настройки Gradle 9.2.1. В `config/mared/workspace-wrapper126` создаётся проверенная локальная копия. При каждом использовании её байты сверяются с ресурсом мода; изменённая копия не перезаписывается молча и не запускается. При необходимости можно по-прежнему указать собственный Wrapper.

Это не устраняет необходимость JDK и зависимостей проекта. Подтверждение выполнения Gradle остаётся обязательным: сборочные скрипты выполняются с правами пользователя. Впервые Gradle и NeoForge-зависимости могут потребовать загрузку. Получившийся мод передаётся в существующий маршрут публикации и согласованного перезапуска, описанный в [изменениях 125](COLLABORATION_PIPELINE_125_RU.md).

Включены 80 воспроизводимых случайных сравнений с восстановлением обоих исходных текстов из diff. Всего 229 проверок.

Это небольшой тестовый проект, а не запуск полного MDK/Minecraft; дистрибутив взят из существующего локального кэша.
