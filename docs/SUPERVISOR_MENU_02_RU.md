# Supervisor menu-02: меню MaRed и возврат на сервер

Дополнение поверх Genesis-supervisor-rework-01. Игра/мод остаются прежней версии. F9 больше не зарегистрирована: удалены её event subscriber и ticker (классы оставлены пустыми для совместимости исходников). `/mared dev restart` сохраняется как дополнительный клиентский путь.

## Как использовать

1. Применить supervisor-rework-01, затем этот патч и пересобрать под Java 21: `.\gradlew.bat build`. Если используется установленный JAR, заменить его новым.
2. На сервере открыть MaRed привычной кнопкой в меню паузы.
3. Нажать «Режим разработки» справа вверху MaRed. Такая же панель доступна прямо в меню паузы и главном меню.
4. Если supervisor ещё не запущен: «Включить и перезапустить». Если уже запущен: «Перезапустить игру».
5. Клиент штатно закроется и перезапустится. После завершения загрузки он попытается снова подключиться к тому же серверу.

Перед действием сохраните изменённые скрипты. Открытие панели не уничтожает runtime редактора; «Назад» возвращает открытые документы и несохранённые изменения. Сам перезапуск не добавляет автосохранение скриптов.

Действие перезапускает только локальный клиент Minecraft. Удалённый сервер не останавливается и не перезапускается; права администратора сервера не нужны. Позиция/инвентарь на удалённом сервере сохраняются самим сервером при отключении игрока. Локальные player-state файлы не применяются к удалённому серверу этим дополнением.

## Возврат

До запроса перезапуска записывается `config/mared/dev-resume.properties`: одноразовое намерение с адресом, именем сервера, выбранной политикой server resource pack, временем и исходным PID. Пароли и токены авторизации в него не записываются. Ошибка записи не закрывает игру. При отказе supervisor намерение отменяется по собственному идентификатору.

Новый клиент, запущенный supervisor, забирает и удаляет намерение до начала подключения. Оно имеет приоритет над последним локальным миром из dev-worlds. Подключение выполняется один раз, когда появился главный экран и исчез загрузочный overlay. Если сервер недоступен, остаётся обычный экран ошибки Minecraft: бесконечного reconnect нет. После ручного отключения повторного входа не происходит.

Намерение старше 10 минут, из будущего, повреждённое или слишком большое не подключает к серверу. В таком сеансе не подхватывается и старый локальный мир. Обычный запуск вне supervisor намерение не исполняет. При перезапуске в одиночной игре сохраняется прежняя настройка автозагрузки мира.

Поддерживаются обычные адреса серверов, порт и IPv6 (их разбор делает ванильный ServerAddress). Адрес может быть адресом прокси, а не конкретного backend-сервера. Realms здесь отклоняется до перезапуска: его возвращение требует отдельного API. При неизвестном адресе текущего сервера перезапуск также отменяется с сообщением. Уже существующая проблема лаунчера/истёкшей авторизации всё ещё может препятствовать новому входу.

## Проверки и ограничения

`verification-menu/check-menu.py` компилирует production DevResumeStore и проверяет реальные файлы: одноразовое потребление, кириллицу/IPv6, защиту исходного PID, отмену собственного запроса, старое/повреждённое намерение, замену серверного намерения локальным. Production MaredDevServerResume проверяется с явно обозначенными API doubles Minecraft/NeoForge: удалённый/одиночный мир/Realm/неизвестный адрес, режим supervisor, главный экран, загрузочный overlay, одна попытка и политика ресурс-пака. Это проверки логики, а не настоящий сетевой вход в Minecraft.

Вызовы Minecraft сверены с Mojang client mappings 1.21.1, вложенными в приложенный исходник (`getCurrentServer`, `hasSingleplayerServer`, `getConnection`, `getOverlay`, `ServerData`, шестипараметрический `ConnectScreen.startConnecting`). Сам файл mappings, игровые JAR и кэши в комплект не скопированы.

Полная Gradle-сборка, работа интерфейса, аутентификация/подключение в Minecraft и Windows здесь не проверены. Ограничения supervisor-rework-01 сохраняются, включая тесты ProcessHandle, пропущенные на этом хосте. Для проверки на ПК: подключитесь к тестовому серверу, откройте MaRed → «Режим разработки», выполните оба вида действий; проверьте одно новое окно, возврат именно на сервер и отсутствие открытия локального мира. Затем отключитесь вручную — автоматического повторного входа быть не должно. Нажатие F9 не должно перезапускать игру. В случае недоступного supervisor клиент должен остаться открытым.
