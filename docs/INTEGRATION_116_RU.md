# Подключение прежних функций —116

## Как объединять большие этапы

2–3 связанных этапа можно выдавать одним патчем. Внутри: контракт → реализация → адаптеры → проверка.
Проверки нужны в каждом выдаваемом патче. Третий пакет может добавлять сквозные испытания,
но не должен быть первым моментом проверки совместимости. Отдельный backend не считается
готовой пользовательской функцией. Гарантировать отсутствие ошибок заранее невозможно.

## Реальные изменения116

- Основная кнопка Script получила режим «Собрать для сервера…»: сохранить → собрать → обзор115
  → подтверждение → текущий owner104. Папка фиксируется при начале сборки, поэтому смена
  настроек не переключает готовый результат на другой сервер. Только серверный мод на этом ПК;
  файлы клиентов этим действием не обновляются. При выборе серверного режима отключается
  автоприменение этого проекта в одиночном мире; другие проекты не затрагиваются.
- Кнопка Сервер определяет текущий owner104/75 и открывает соответствующую существующую панель.
  Проверенный локальный владелец папки — отдельный контекст от MaRed-роли сетевого игрока.
  Отказ сервера не выдаёт сетевое разрешение; OP не становится maop.
- В продвинутых настройках восстановлены входы: обновление клиента, история перезапусков клиента,
  мои права MaRed и инструменты75 (выпуск, HTTPS, сроки, восстановление, участники).
  Локальная публикация не переключается самовольно на чужой подключённый сервер.
- Старый мастер проверяет тип владельца до запуска. Для104 показывает отсутствие rollout-адаптера,
  не снимая защиту SERVER104_UPDATE_COORDINATOR_REQUIRED.
- Служебные процессы подписи/HTTPS/восстановления/панели используют общий транспорт: без shell,
  без наследования посторонних agents/Python путей, с закрытым stdin и файловым stdout.
  Большой ответ не блокирует pipe. Таймаут/interrupt закрывают только короткий helper,
  не игру и не её lifetime owner.
- UI учитывает срок ответа105, отказ отправки отменяет ожидание возврата клиента. Распаковщик
  принимает растущий bundle, сохраняя лимиты, запрет обхода путей, повторов регистра и перезаписи.

Главный экран не получает сетку дополнительных кнопок: инструменты находятся в продвинутых настройках.

## Что ещё не соединено

**Нет,116 не означает «всё подключено».** Полный реестр29 групп — INTEGRATION_CATALOG_116.json.
Включены раннее ядро35, packages37, native/LIVE36–57, waiting/cohort, пилот58–67,
доставка/публикация/допуск, текущий supervisor, Script и Workspace112.
Пустые/заменённые экраны и конкурирующие старые автоматы не включаются параллельно ради ссылок.

Главный незакрытый блок — адаптер массового обновления к папочному owner104:

1. Подписанная CLIENT/SERVER пара, текущий запуск и фактические составы обеих сторон.
2. Подготовка до остановки, согласие30с, отказ/отмена до перезапуска клиентов.
3. Control pump внешнего владельца сохраняется во время смены серверной JVM.
4. Save+stop+Changes104 вместо копии поколения/мира75.
5. Cohort/25%/допуск/reconnect/отмена связаны с фактическим новым запуском.
6. Холодное восстановление подписи, identity, ревизии и транзакции обеих сторон.
7. Единый approval для Script/CLI/watch/импорта/публикации. BuildSnapshot84 пока не полный
   утверждённый исходный snapshot с флажками всех файлов.
8. Соотнести ранние UpdateMachine/Waiting/PlayerUpdate модели с одним авторитетным автоматом.
9. Настоящие2 компьютера/3 Minecraft-клиента, включая обрыв, отзыв прав и падение кандидата.

Это продолжающаяся интеграция существующих механизмов. Новые OT/курсоры/ACL/общие текстуры отложены.
Реестр явно отличает подключённый код, ограниченно подтверждённые пользователем сценарии,
legacy-only пути, частичные функции, отдельные модели и заменённые элементы.

## Проверка и диагностика

    py .\tools\integration_audit116.py .

Это проверка наличия исходников и запись оставшихся связей; она не подтверждает работу Minecraft
и не даёт процент готовности. Источник оставшейся работы — blocking_connections в реестре.

Короткая ручная проверка после сборки:
1. Script → режим «Собрать для сервера…»: после успешной сборки открывается обзор115 с выбранной
   ранее папкой; клиент не перезапускается вместо сервера. Отмена не меняет JAR/сервер.
2. Сервер → продвинутые инструменты: обновление клиента и история открываются в Minecraft.
3. На75 открывается удалённая панель, на104 — простая. Offline-локальный сервер с собственной
   выбранной папкой использует локальный путь. Чужой сервер без maop отказывает.
4. Для104 мастер массовой публикации объясняет отсутствие адаптера и не начинает переход.
5. В latest.log маркер «Genesis integration116» показывает фактически выбранный маршрут.

Windows/JDK21/рендер/сетевые Minecraft-сессии здесь не запускались. Child-JVM/filesystem проверки
и API-компиляция не выдаются за настоящую приёмку.
