## Для чего нужна вкладка
Scripts — рабочее пространство исходного кода. Здесь можно создавать проекты, импортировать папки, редактировать текстовые файлы, организовывать каталоги, сохранять изменения, запускать самостоятельные Java-программы и собирать настроенные Gradle-проекты. Help работает без подключения к интернету. Его примеры не запускаются при открытии статьи: кнопка копирования только помещает текст в буфер обмена.

Java поддерживается настоящим компилятором и отдельной JVM. Java-программа с main и мод NeoForge — разные типы запуска. Minecraft API доступен Gradle-проекту при наличии правильных зависимостей; обычный Java-runner не получает объекты мира, игрока и сервер автоматически. MR и его команды относятся к Commands, не являются языком или API Scripts.

Python, Rust и C++ можно использовать как исходные тексты проекта, редактировать и экспортировать. Их компиляторы, интерпретаторы и игровые runtime в текущей версии не подключены. Серверные Java-модули Genesis можно применять и заменять в одиночном мире без перезахода. Multiplayer, LAN, универсальная горячая установка обычных модов, полноценный отладчик и автоматический рефакторинг пока отсутствуют.

## Как читать Help
В широком окне слева находится список статей, справа — выбранная статья. Поиск проверяет заголовок, пояснения и весь текст, включая примеры. Несколько слов должны одновременно встретиться в статье. Категории и закладки дополнительно ограничивают результаты. Чтобы убрать ограничение, верните «Все» и переберите категории до общего списка.

Кнопки «Назад» и «Вперёд» сохраняют историю чтения и положение прокрутки статьи. «Копия текста» копирует всю статью; «Скопировать код» — только исходный пример без интерфейсных надписей. Закладки и история хранятся в текущем окне Genesis, не переносятся между запусками игры.

Help открывается отдельным окном: его можно перемещать за заголовок и менять размер. «Dock right» закрепляет уменьшенную версию справа от workspace; «Open window» возвращает отдельное окно. В узкой панели кнопка «Разделы» переключает список и статью, а поиск сразу показывает список результатов. Изменение размеров не сбрасывает открытую статью.

Картинки здесь — схемы процесса, а пошаговый блок иллюстрирует первый запуск. Это не запись Minecraft и не видеоплеер. Просмотр шагов не выполняет команды, не сохраняет файлы и не запускает сборку.

## Настройка путей Java и Gradle
В «Запуск → Путь к папке JDK» можно вставить абсолютный Windows-путь с пробелами и обратными слешами, например `C:\Program Files\Java\jdk-21.0.4`. Кавычки из «Копировать как путь» снимаются автоматически. Принимаются также папка `bin`, `java.exe` и `javac.exe`: сохраняется корневая папка JDK. Нужен полный JDK 21 или новее, включая `bin/java`, `bin/javac` и файл `release`. Обычная Java среды Minecraft может не содержать компилятор. Явно сохранённый путь имеет приоритет; без него проверяется `JAVA_HOME`, затем Java клиента. Изменённые или удалённые инструменты проверяются повторно перед операцией.

Сохранённый JDK используется и для локального Java-запуска, и для компиляции горячего серверного модуля. Для этих действий Wrapper не нужен. `WorldModule` запускается через «Применить на сервере» и метод `onEnable`; добавлять `main` не требуется. «Запустить Java» вызывает `main(String[] args)` в отдельной JVM и не применяет модуль к миру.

Gradle требует настоящий `gradle-wrapper.jar` с `gradle-wrapper.properties` рядом. Можно выбрать сам JAR, properties, папку Wrapper или корень проекта с `gradle/wrapper`. `gradlew.bat` не является Wrapper JAR. Wrapper выбранного проекта имеет приоритет над общим; повреждённый Wrapper проекта выдаёт ошибку и не подменяется другим. Если Wrapper отсутствует, выберите его из доверенного рабочего Gradle-проекта. Сохранение пути ничего не скачивает и не запускает; Gradle загружает дистрибутив и зависимости только при запросе задач или сборке. Ошибки сети и несовместимости остаются в отчёте Gradle.

## 1. Создайте проект
Откройте меню Project в верхней панели Scripts и выберите создание Java-проекта. Задайте уникальное имя. Выберите корень нового проекта в проводнике: цвет имени и направляющих отмечает активный проект. Для этого урока нужен самостоятельный Java-проект, а не импортированный Gradle-проект.

Создайте Main.java в корне или в папке src. Если шаблон уже создал этот файл, откройте его. Путь при создании зависит от выбранной папки: сначала выберите место назначения в дереве. Диалог подставляет рабочий каталог; проверяйте итоговое имя и расширение перед подтверждением.
## 2. Напишите код
Скопируйте пример кнопкой ниже и вставьте его в редактор Main.java. Public-класс Main должен находиться в файле Main.java. В этом примере package отсутствует.
```java
public class Main {
    public static void main(String[] args) {
        System.out.println("Hello, Genesis");
    }
}
```
## 3. Выберите запуск
Выберите Main.java в проводнике. Откройте стрелку рядом с кнопкой запуска и выберите «Запуск Java-файла». Сам выбор режима код ещё не запускает. Нажмите основную кнопку запуска. В диалоге точки входа проверьте имя Main и подтвердите. Ctrl+R использует выбранный режим.

Компилируется весь набор Java-источников проекта, а запускается выбранный класс с main. Текст открытых документов берётся с учётом черновиков. Если другой исходник содержит ошибку, исправить нужно и его: выбранный файл не изолирован от остальных классов.
## 4. Проверьте результат
В нижней панели логов ожидается Hello, Genesis и успешный статус завершения. Панель раскрывается стрелкой на её границе; размер меняется перетаскиванием разделителя. Если ничего не видно, сначала откройте логи, затем проверьте статус запуска.

Измените строку на Hello, friend и запустите снова. Java-runner увидит открытый черновик без обязательного сохранения. Но чтобы оставить изменение на диске после работы, используйте Save / Save all. Запуск не заменяет сохранение.
## Если не получилось
«Compiler unavailable»: игре нужен полный JDK с jdk.compiler. «Main class not found»: проверьте имя класса и package. «Compile error»: прочитайте первую ошибку и исправьте исходник. Не переключайтесь на «Сборка мода» для этого примера: это другой механизм.

## Проект как папка
Проект — отдельная папка с исходниками, ресурсами и конфигурацией. В проводнике можно раскрыть несколько корней одновременно. Стрелка раскрывает дерево; щелчок по имени выбирает проект. Активный корень и непрерывные линии вложенности используют цвет Logic, остальные остаются нейтральными. Папки внутри проекта не являются отдельными проектами.

Файл другого раскрытого проекта сначала переключает контекст проекта, затем открывается в редакторе. Сворачивание корня не закрывает его документы и не уничтожает черновики. Перед сборкой смотрите на выбранный проект в проводнике: именно он определяет цель запуска, даже если прежде редактировался другой документ.
## Где лежат данные
Рабочие проекты находятся в config/mared/script_projects относительно папки запуска Minecraft. Команда копирования пути проекта помещает точный абсолютный путь в буфер обмена: используйте его в Проводнике Windows. В dev-запуске папка config может находиться внутри run, а не рядом с исходниками MaRed.

genesis-project.properties описывает тип проекта и параметры Genesis. Это служебная конфигурация проекта; изменение произвольных полей без понимания формата может нарушить импорт или запуск. Пользовательские файлы могут лежать в своих подпапках. Не переносите вручную рабочий корень во время сохранения, импорта или сборки.
## Состояние и обновление
Проводник рисует кэшированное дерево. После изменений внешней программой нажмите «Обновить», чтобы перечитать файлы; это не означает перезапись открытых черновиков. До 16 деревьев проектов одновременно сохраняются в кэше, старое дерево при превышении сворачивается. Документы сохраняются отдельно от этого кэша.

После закрытия восстанавливаются поддерживаемый контекст выбранного проекта и папок. Список одновременно раскрытых корней и выбранный режим запуска существуют в текущем окне. Не считайте их постоянными настройками проекта.

## Поиск и клавиатура
Поле поиска находится сверху по центру. Нажмите на него и вводите текст: под полем появятся пять режимов и результаты. Щелчок по режиму или Tab переключает режим с сохранением запроса. Стрелки выбирают результат, Enter открывает его, Esc закрывает поиск.

- Ctrl+P — файл по имени или относительному пути в выбранном проекте. Пустой запрос показывает весь загруженный список файлов, до 4096; длинный список прокручивается. Бинарный файл показывается в дереве, а не открывается как текст.
- Ctrl+F — текст в текущем файле, включая несохранённый черновик; найденное выделяется.
- Ctrl+Shift+F — текст в выбранном проекте. Открытые документы ищутся по их текущему тексту, остальные — по сохранённым файлам. Результат содержит путь, строку и фрагмент; Enter открывает нужный файл. Если текст изменился после поиска, повторите запрос.
- Ctrl+G — переход к существующей строке текущего файла; нумерация начинается с 1.
- Ctrl+O — фильтруемый список открытых файлов выбранного проекта; переход сохраняет черновик.

Текстовый поиск регистронезависимый, буквальный, без регулярных выражений и замены. Непустой запрос ограничен 200 результатами; уточняйте запрос при ограничении. Поиск по проекту ограничен 4096 файлами и 8 МиБ текста, выполняется в отдельном потоке и отменяется при закрытии. Ошибки чтения обозначаются отдельно, доступные результаты сохраняются. После внешних изменений списка файлов используйте Refresh. В режиме просмотра поиск и переходы доступны.

Shift+стрелки расширяет выделение, Ctrl+Shift+Left/Right выделяет по словам, Ctrl+Shift+Up/Down — до границы абзаца. Shift+Home/End — до начала/конца строки; Ctrl+Shift+Home/End — до начала/конца документа. Обычные Left/Right снимают выделение с переходом к его краю. Ctrl+Shift+Z повторяет отменённое редактирование.

Новый файл с корректным Java-именем получает public class по имени файла. Для стандартных src/main/java, src/test/java, src и tests package выводится из подпапок. Пользовательские sourceSets автоматически не определяются. module-info.java, package-info.java и некорректные имена класса остаются пустыми. Импортированные и существующие файлы не изменяются.

## Создание и выбор
Выберите корень или нужную папку в проводнике. В меню File или контекстном меню выберите создание файла либо папки. Создание вложенного пути выполняется внутри выбранного проекта; пути наружу и символические ссылки не допускаются. Для обычного исходника используйте подходящее расширение, например .java. Двоичные файлы видны в дереве, но не открываются как текстовый исходник.

Правый клик по проекту или папке → «Создать файл» / «Создать папку». Введите только имя (для файла — с расширением, например Block.java), без полного пути. Создание идёт внутри выбранной папки; новый файл сразу открывается, папка появляется в дереве. Правый клик по файлу создаёт рядом с ним; по свободному месту — в корне текущего проекта.

Стрелки Left/Right сворачивают и раскрывают папки; Up/Down перемещают выбор. Enter открывает выбранный текстовый файл. Правый щелчок устанавливает контекст именно той строки, по которой нажали: операции должны относиться к ней, а не к ранее открытому документу.
## Переименование
F2 и соответствующий пункт меню переименовывают выбранный файл или папку. Это операция над путём, а не Java-рефакторинг. При переименовании Main.java исправьте также имя public-класса, импорты и при необходимости точку входа. Переименование package-папки само по себе не меняет package в коде.

Редактор проверяет конфликты путей и сохранность черновиков. Если операция отказана из-за несохранённых документов, сохраните их или осознанно завершите работу с ними, затем повторите. Существующий файл назначения не перезаписывается молча.
## Копирование и удаление
Ctrl+C в проводнике запоминает выбранный файл или папку для копирования; Ctrl+V вставляет в выбранную папку. Это отличается от Ctrl+C текста в самом редакторе. В меню есть отдельная операция копирования пути в системный буфер. Вставка не перемещает оригинал и откажется при конфликте имени. Копирование между разными проектами этим буфером пока не поддерживается: выбирайте другую папку внутри исходного проекта.

Delete запускает удаление через интерфейс подтверждения. Поддерживается внутреннее обратимое удаление и восстановление; восстановление не затирает занятый путь. Не рассчитывайте на Корзину Windows как на хранилище Genesis. После восстановления проверьте дерево и файлы.
## Когда файлов много
Разделите код по пакетам: например src/demo/Main.java и src/demo/logic/Calculator.java. Ресурсы держите отдельно от исходников. Не сохраняйте JAR и архивы как .java. Имена с пробелами и Unicode поддерживаются в пределах проверок пути; Java-имена классов и package подчиняются правилам языка.

## Открытый текст и диск
Редактирование сначала изменяет документ в памяти. Save записывает активный документ, Save all — изменённые документы. Переключение проектов и сворачивание папок не выполняет скрытого сохранения. История undo/redo относится к документу; переключение не должно превращаться в удаление черновика.

Для локального Java-запуска открытые черновики подставляются в снимок исходников. Gradle работает с файлами на диске, поэтому перед сборкой редактор выполняет подготовку сохранения. Ошибка сохранения или конфликт останавливает подготовку: старый текст на диске не должен выдаваться за сборку нового кода.
## Конфликт с внешним редактором
Если файл на диске изменился после чтения, редактор проверяет исходную сохранённую версию. При конфликте не перезаписывайте файл вслепую. Скопируйте свой черновик в безопасное место, сравните его с внешней версией, затем явно решите, какую версию оставить. «Обновить» дерево не является командой принудительной перезаписи.

Закрытие документа с несохранёнными изменениями требует решения о сохранении либо отказе от них. Отказ от черновика — отдельное действие; обычный переход на другой файл не должен его уничтожать.
## Восстановление
Редактор ведёт данные восстановления и контекст рабочего пространства. Если после закрытия или аварии предлагается восстановление, проверьте текст и базовую версию перед сохранением. Recovery не заменяет резервную копию проекта, а запись восстановления может не успеть завершиться при жёстком отключении процесса.

Одновременно открыто до 16 документов; при большом проекте закрывайте уже не нужные вкладки. Не держите десятки несохранённых файлов как единственную копию работы. Для передачи другу используйте экспорт проекта, для устойчивой истории — свой внешний контроль версий.

## Логи Scripts
Нижняя панель теперь поддерживает поиск, фильтры, выделение текста, копирование, очистку и экспорт, как панель Commands. Записи и фильтры Scripts независимы. Категории: editor, java, gradle, server, tools; ошибки исполнения имеют уровень ERROR. Фильтры Scripts не меняют Commands. Очистка истории не удаляет отчёты сборки, вывод последней операции и работающий модуль мира. Экспорт создаёт новый UTF-8-файл .log и копирует путь; предыдущие экспорты не заменяются.

Щёлкните по логам для фокуса: Ctrl+F ищет внутри логов, Ctrl+A выбирает видимые строки, Ctrl+C копирует выделенное или все видимые строки. При фокусе в поле поиска эти клавиши работают с полем. Esc закрывает поиск/фильтры логов. В компактном заголовке E — экспорт, X — очистка, C — копирование, / — поиск, F — фильтры. Длинная строка визуально обрезается шириной панели; копирование и экспорт сохраняют записанный текст. Размер истории ограничен настройкой, а объём вывода процессов ограничен отдельно.

## Точка входа
Запускаемый класс должен иметь public static void main(String[] args). Имя точки входа — полное имя класса, не путь к файлу. Для package demo и класса Main введите demo.Main. Не добавляйте .java, .class, слеши или аргументы командной строки в поле имени класса.

В режиме Java-файла начальное имя выводится из имени файла и простого объявления package открытого документа. Это подсказка, а не полноценный анализатор Java; вложенные классы и необычные объявления требуют проверки. Имя в этом диалоге относится к запуску и не переписывает постоянную точку входа проекта.
## Что компилируется
Runner собирает Java-источники выбранного проекта, подставляет открытые черновики, добавляет локальные JAR и resources, компилирует во временное рабочее пространство и запускает выбранный main отдельным процессом. Изменения текста после начала не передаются уже запущенному процессу: новый запуск получает новый снимок.

Ошибки компиляции других классов останавливают запуск. Чтобы проверить отдельную функцию, напишите небольшой main, вызывающий её, либо используйте тестовую Gradle-задачу своего проекта. Кнопка Java-файла не предоставляет брейкпоинты и пошаговый debugger.

## Файл src/demo/Main.java
```java
package demo;

        System.out.println("sum = " + result);
```

## Локальные JAR
Для самостоятельного Java-проекта используйте папку libraries в корне проекта. Команда копирования пути библиотек даёт точное место. Поместите туда готовые JAR через файловую систему, обновите дерево и повторите запуск. Библиотеки передаются и компилятору, и JVM.

Runner не скачивает Maven-зависимости, не устанавливает любые пакеты по имени и не подключает нативные библиотеки C++/Rust автоматически. Если JAR требует другие JAR, добавьте их отдельно. Manifest Class-Path, Java-агенты и произвольные опасные пути не являются способом обойти проверку. Несовместимый Java bytecode или отсутствующая транзитивная зависимость приводят к ошибке запуска.
## Ресурсы
Папка resources в корне самостоятельного Java-проекта становится classpath-ресурсами. Например resources/message.txt читается как /message.txt. Создайте UTF-8 файл со строкой Hello from resource и используйте пример в Main.java:
```java
import java.nio.charset.StandardCharsets;
public class Main {
    public static void main(String[] args) throws Exception {
        try (var in = Main.class.getResourceAsStream("/message.txt")) {
            if (in == null) throw new IllegalStateException("message.txt missing");
            System.out.println(new String(in.readAllBytes(), StandardCharsets.UTF_8));
        }
    }
}
```
## В Gradle-проекте
Зависимости объявляются в build.gradle или build.gradle.kts, обычные ресурсы лежат в src/main/resources. Импортированный Gradle-проект использует свои sourceSets, repositories и dependencies. Он не получает локальную папку libraries как универсальный classpath по правилам runner. Проверяйте фактическую конфигурацию проекта и его Wrapper.

JAR библиотеки не является модом сам по себе. Чтобы получить самостоятельный игровой мод, нужны metadata загрузчика, зависимости, корректные entrypoints и обработка ресурсов в Gradle. Экспорт исходников лишь сохраняет материалы проекта.

## Устойчивость сборки
Gradle-проект может иметь только settings.gradle или settings.gradle.kts в корне, с build-файлами в модулях. Поддерживаются задачи модулей, имена с цифрами, подчёркиваниями и Unicode. Wrapper повторно проверяется перед запуском. Launcher использует выбранный JDK; org.gradle.java.home передаётся явно. Если проект содержит gradle/gradle-daemon-jvm.properties, критерии daemon JVM Gradle имеют более высокий приоритет; это отмечается в отчёте. Toolchain и загрузка JDK определяются конфигурацией самого проекта.

В «Запуск» и полных настройках Java/Gradle доступны параметры выбранного проекта: тайм-аут 1–1440 минут и workers 0–64. По умолчанию: 10 минут и 2 workers. Значение 0 оставляет число workers настройкам Gradle. Эти параметры сохраняются в genesis-project.properties. При тайм-ауте/отмене процесс завершается; последующая сборка доступна снова.

Сохранение файлов собираемого проекта заблокировано до завершения/остановки Gradle, но редактировать черновик можно. После сохранения изменённых исходников прежний отчёт сборки сбрасывается: перед применением JAR нужна новая сборка. Ошибка или отмена подготовки заменяет прежний успешный отчёт и не предлагает старые артефакты. В отчёт пишутся путь проекта, JDK launcher, Wrapper, задача, лимиты и причина завершения.
## Два Java-окружения
Игра и локальный Java-runner используют Java-окружение клиента. В настройке инструментов сборки указывается отдельный путь JDK для Gradle. Это не переключение JVM уже запущенной игры. Для текущего NeoForge-шаблона требуется полный JDK 21; путь должен вести в каталог JDK, содержащий bin/java и bin/javac, а не в java.exe.

Выберите настройку инструментов в Project / Run. Укажите абсолютный путь, например C:/Program Files/Java/jdk-21. В поле Wrapper JAR указывается полный путь к gradle-wrapper.jar, а не к gradlew.bat. Проверки требуют настоящий WrapperMain и корректную конфигурацию distributionUrl.
## Wrapper проекта
Импортированный Gradle-проект использует собственный gradle/wrapper/gradle-wrapper.jar вместе с properties. Если собственный Wrapper повреждён, редактор не подменяет его молча глобальным: исправьте исходный проект или его копию. Для проекта без собственного Wrapper нужен явно настроенный допустимый Wrapper по правилам инструментов.

build.gradle, settings.gradle и gradle.properties остаются конфигурацией проекта. Не заменяйте их конфигурацией MaRed лишь ради успешной проверки. ## Какой путь выбирать
build — задача корня. module:build или :module:build адресует модуль, если такой путь реально существует. test запускает тесты только при наличии соответствующей задачи и настроенного test suite. runClient запускает отдельный dev-клиент только в проектах, где плагин предоставляет эту задачу; это не горячая перезагрузка текущего мира.

Поле задачи принимает один допустимый путь, без пробелов, CLI-флагов и цепочек команд. Для сложного процесса определите собственную Gradle-задачу в проекте. Список может быть ограничен по объёму, а динамические rules не превращаются автоматически в готовые строки задач.

## Читайте статус и первую причину
При неуспешной сборке откройте нижние логи, затем отчёт/диагностику. Запишите задачу, проект и первую содержательную ошибку. Строка BUILD FAILED — итог, обычно причина находится выше. Deprecated API и предупреждения Gradle сами по себе не обязательно ломают сборку.

Диагностика распознаёт поддерживаемые позиции path:line:column и формы ошибок Java/Gradle. Выбор доступной записи открывает локальный исходник в соответствующей позиции. Абсолютные Windows-пути, Unicode и вложенные файлы поддерживаются в рамках проверки корня проекта.
## Защита пути
Путь из чужого лога не открывается как произвольный файл компьютера. Внешние пути, traversal, URL и недопустимые номера строк не используются для навигации. Такая запись всё ещё может быть полезна как текст ошибки. Ссылка на файл зависимости вне проекта не означает, что её можно редактировать внутри этого workspace.
## Пределы анализа
Парсер не является Java language server: он не знает всех семантических связей, не понимает любой формат стороннего плагина и не исправляет код автоматически. Число записей и объём вывода ограничены. При обрезанном логе сосредоточьтесь на воспроизводимой ошибке или отдельной задаче вместо ожидания бесконечного протокола.

Java-runner показывает ошибки компилятора и stack trace процесса. System.out подходит для проверок значений, System.err — для диагностических сообщений. Наличие вывода не гарантирует успех: программа может написать строку и затем завершиться с исключением.

## Поиск результатов
После успешной сборки откройте список артефактов. Поиск охватывает build/libs и build/distributions корня и поддерживаемых вложенных модулей, без сканирования кэшей как результатов. JAR, ZIP и другие архивы могут быть разного назначения. sources.jar и javadoc.jar не являются установленным игровым модом.

Задача test может завершиться успешно, не создав новый JAR. В каталоге build могут остаться файлы прежней сборки. Снимок артефактов означает «этот файл обнаружен после задачи», а не доказательство, что именно эта задача создала его заново.
## Выдача файла
Выберите файл и используйте копирование/выдачу. Перед выдачей проверяются путь, размер и SHA-256. Если файл изменён или заменён после отчёта, операция отказывается выдавать устаревший снимок. Повторите сборку или актуальную проверку вместо обхода ошибки.

Выданный файл копируется отдельно в .artifacts рабочего хранилища, его путь можно получить через буфер обмена. Старые выдачи не перезаписываются молча. Отмена выдачи не публикует частичную копию как готовый результат.
## Будет ли JAR работать без MaRed
Да, если это обычный правильно настроенный мод с собственным entrypoint и metadata, а его код и зависимости не требуют MaRed/Genesis. Шаблон NeoForge создан именно без обязательной зависимости от редактора. Произвольная Java-библиотека или ZIP проекта этим условием не обладает автоматически.

Проверьте совпадение версий Minecraft и NeoForge, установите необходимые зависимости и протестируйте JAR в отдельной игре. Установка обычного NeoForge-мода выполняется стандартно через mods и перезапуск; текущий редактор не устанавливает его горячо в уже работающий мир.

## Что сохраняется
Поддерживаемая структура, исходники, двоичные ресурсы, конфигурация и скрытые проектные файлы сохраняются в пределах правил импорта. Кэши и внешние ссылки не являются способом подключить произвольную часть файловой системы. Слишком большой проект, символьные ссылки, недопустимый путь и изменение содержимого во время копирования могут привести к отказу.

Перед повтором остановите внешние программы, которые действительно меняют исходники. Не отключайте проверку согласованности ради исчезновения ошибки: частичная смесь разных версий проекта не пригодна для надёжной сборки.

## Менеджер зависимостей проекта
Run → «Зависимости проекта» или Settings → Tools → «Зависимости проекта» открывает мастер. Нужен build.gradle (Groovy). Maven-координаты вводятся как group:artifact:version[:classifier]; поддерживаются фиксированные версии. HTTPS Maven-репозитории можно добавить и удалить через этот же мастер. Gradle загружает зависимости при следующей сборке.

Java-библиотеку можно подключить при компиляции и запуске, только при компиляции или упаковать через Jar-in-Jar. Упаковка доступна для Maven-библиотек без classifier в проекте NeoGradle; задача build вызывает jarJar. Для установки используйте результат jarJar, содержащий вложенные библиотеки. Обычный JAR без упаковки тоже может присутствовать в build/libs.

Для зависимости от мода укажите его ID, Maven-координаты, диапазон версий, обязательность и сторону. Менеджер обновляет neoforge.mods.toml. Другой мод остаётся отдельным JAR; у игрока он должен быть установлен, если зависимость обязательная. Необязательный мод подключается только при компиляции, поэтому код должен учитывать его отсутствие.

Переключатель libraries подключает локальные JAR к Gradle и запускам NeoGradle; он создаёт папку и проверяет архивы. Это подключение не упаковывает локальные JAR. Maven-зависимости доступны при сборке через Gradle, не при прямом Run Java.

Менеджер сохраняет genesis-dependencies.properties и genesis-dependencies.gradle, добавляет управляемые блоки в build.gradle и метаданные. Эти файлы входят в экспорт. Сначала сохраните открытые файлы настроек; внешние конфликты и ручные изменения управляемых блоков не перезаписываются. Поддерживается один мод в метаданных и NeoGradle для зависимостей модов/упаковки.

## Локальный Java-runner
До 512 исходников, до 4 MiB на текстовый файл и 16 MiB суммарно для исходников. До 32 локальных JAR, 8 MiB на JAR и 64 MiB суммарно; содержимое архива также проверяется. До 512 ресурсов, 8 MiB на файл и 32 MiB суммарно. Пути проверяются, символические ссылки и выход наружу не допускаются.

Текущие стандартные лимиты запуска: компиляция 20 секунд, выполнение 10 секунд, вывод 64 KiB и JVM heap 128 MiB. Heap не равен всей памяти процесса. Лимиты не являются sandbox ОС и не превращают Java в безопасный язык для чужого кода.
## Gradle и результаты
Стандартный таймаут Gradle-операции — 10 минут. Вывод ограничен 256 Ki символов. При больших выводах сохраняется ограниченный хвост с отметкой обрезки. Список задач — до 512 записей; допустимый путь задачи до 192 символов, без свободных флагов командной строки. Диагностика также ограничена и не заменяет полный анализ IDE.

Поиск артефактов ограничен глубиной 16, числом просмотренных entries 10000 и количеством результатов 128; один артефакт до 256 MiB, общий объём до 512 MiB. Эти пределы не гарантируют поддержку любого гигантского проекта и могут потребовать отдельной доработки.

## Серверное выполнение
Локальный main работает на компьютере клиента. Он не получает права оператора и не выполняет код удалённого сервера. Gradle build делает output проекта. Готовый обычный мод устанавливается на нужную сторону по правилам загрузчика и самого мода.

Будущий сетевой runtime потребует отдельной архитектуры разрешений, протокола распространения, совместимости клиента/сервера и жизненного цикла. Для одиночного мира уже есть применение ServerModule без выхода. Сетевой загрузки и применения кода удалённого сервера пока нет. Универсальную горячую замену регистрации объектов обычного NeoForge-мода текущие функции не предоставляют.

## Верхняя строка
Поле поиска принимает до 160 символов. Ctrl+F переводит фокус туда. Поиск ведётся по всему встроенному руководству, без сети. Ctrl+A в поле выбирает весь запрос для замены следующим вводом; Backspace удаляет выбранное целиком или последний символ. Ctrl+V вставляет ограниченный текст из буфера без управляющих символов. Enter открывает первый отфильтрованный результат.

Категории последовательно переключаются кнопкой списка. «Закладки» оставляет только отмеченные статьи, «Все» возвращает весь список. Пустой результат означает отсутствие совпадений при текущих фильтрах; попробуйте убрать запрос и фильтры.
## Чтение
Назад/Вперёд перемещают по истории статей. Кнопка закладки добавляет или снимает отметку текущей статьи. «Копия текста» и Ctrl+C при фокусе Help копируют весь текст статьи. У каждого исходника есть отдельная кнопка копирования только кода. Ссылки внутри статьи открывают связанную тему без внешнего браузера.

Колесо над оглавлением прокручивает список, над статьёй — статью. Home/End переходят к началу/концу статьи, PageUp/PageDown прокручивают её; Up/Down дают меньший шаг. Клавиши чтения используются, когда поле поиска не захватило ввод. Esc закрывает Help через оболочку Genesis.

## Быстрый пример
Зайдите в одиночный мир, не открывая LAN. В Scripts → Project выберите «Создать серверный Java-модуль». Укажите уникальное имя. Откроется src/WorldModule.java, а стрелка запуска выберет «Применить в мире». Проект включает настоящий API JAR в libraries.

Нажмите основную кнопку и подтвердите WorldModule как класс входа. Код компилируется отдельным javac; после подготовки onEnable выполняется на потоке встроенного сервера. Шаблон устанавливает полдень в overworld, отправляет сообщение и подписывается на тики. Открытые черновики участвуют в компиляции без автоматического Save.

## Минимальный исходник
```java
import com.fixmer.genesis.technology.server.ServerModule;
import com.fixmer.genesis.technology.server.ServerContext;

public final class WorldModule implements ServerModule {
    @Override public void onEnable(ServerContext context) {
        context.setDayTime("minecraft:overworld", 6000);
        context.broadcast("Applied without reconnecting!");
    }
}
```
## Повторное применение
Измените 6000 на 18000, нажмите применение и подтвердите тот же entry. Мир станет ночным без перезахода. Закрытие Genesis не останавливает уже применённый модуль. Если игра при открытом меню поставила одиночный сервер на паузу, периодические тики возобновятся вместе с миром.

Ошибку компиляции или onEnable редактор покажет в логах. Прежняя версия сохраняется при отказе новой. Класс должен иметь публичный конструктор без аргументов и реализовывать ServerModule. Обычные main и @Mod не подходят. Конструктор и статическая инициализация тоже исполняются при загрузке: не помещайте туда действия над миром.
## Управление
В Run есть состояние, остановка и возврат предыдущей версии. Статус показывает поколение кода, активность и количество обработчиков. Остановка удаляет обработчики и обе сохранённые версии этого проекта. Выход из мира также очищает runtime. Не переносите ссылку ServerContext в другой мир или поток.

## Жизненный цикл
onEnable(ServerContext) вызывается при применении. onDisable() вызывается при замене, остановке, ошибке периодического обработчика и закрытии мира. Контекст отзывается перед onDisable: используйте этот метод для освобождения своих ресурсов, не для новых изменений мира. Управляемые подписки очищаются автоматически; свои внешние потоки и подписки NeoForge нужно освобождать самостоятельно.

API не зависит от MR, Commands и Minecraft-классов. API_VERSION равен 1. Все методы контекста разрешены на серверном потоке внутри текущей сессии. Вызов из собственного worker-thread или после остановки откажется работать. nativeServer() возвращает встроенный MinecraftServer как Object; приведением типа можно пользоваться в Gradle-модуле с Minecraft dependencies.
## Методы
owner() — UUID локального игрока; worldSession() — идентификатор текущей сессии, generation() — номер применённой версии.
log(text) — строка в логах Scripts, до 2048 символов; broadcast(text) — системное сообщение игрокам текущего мира, до 512 символов.
setDayTime(dimension, ticks) — время указанного существующего измерения. setWeather(durationTicks, raining, thundering) — погода overworld. Гроза требует дождя, длительность 1–1200000 тиков.
setBlock(dimension, x, y, z, blockId) — существующий блок с default state в уже загруженном чанке. Например minecraft:stone. Неверная высота, отсутствующий блок/измерение и незагруженный чанк приводят к отказу; этот метод не генерирует чанки.
state(key) / state(key, value) — строковые значения, передаваемые следующей версии. null удаляет ключ. До 128 ключей, ключ до 128 символов, значение до 4096. Это память текущей сессии, не запись на диск.
onTick(LongConsumer) — обработчик серверных тиков runtime. afterTicks(delay, Runnable) — одноразовая задача. Оба возвращают Subscription с close(). До 256 задач/подписок на модуль; задержка 1–1200000 тиков.
## Периодическая логика
```java
import com.fixmer.genesis.technology.server.*;
public final class WorldModule implements ServerModule {
    private ServerContext.Subscription task;
    public void onEnable(ServerContext context) {
        task = context.onTick(tick -> {
            if (tick % 200 == 0) context.log("Ten seconds of running world ticks");
        });
        context.afterTicks(40, () -> context.broadcast("Two seconds later"));
    }
    public void onDisable() {
        if (task != null) task.close();
    }
}
```
## Ошибка и права
Java-модуль выполняется внутри JVM игры с её правами. Это не sandbox. Бесконечный цикл, System.exit, unmanaged threads и прямые изменения через nativeServer могут зависнуть или завершить игру. Здесь нет обещания безопасно принудительно остановить произвольный Java-код.

Для вернувшего управление onEnable проверяется предел 200 ms, для периодических callbacks — 10 ms на модуль за тик. Превышение или исключение отключает управляемые callbacks. Замер не прерывает зависший поток. Долгую работу выполняйте отдельно и проектируйте явную передачу результатов на серверный поток; сам ServerContext из worker вызывать нельзя.

## Замена и откат
Для проекта хранится активный снимок и один предыдущий успешный снимок. У каждой активации новый classloader. После замены старые управляемые обработчики прекращаются, вызывается onDisable, classloader закрывается. Предыдущие файлы сохраняются для возможного возврата; более старые удаляются.

Возврат загружает предыдущий код с новым экземпляром и текущим строковым state. Это откат кода, не истории мира и не значений state. Снова выполняется onEnable. Если он не подходит к новому состоянию или вызывает ошибку, текущая версия остаётся. State не сохраняется после выхода из мира.

Изменения через API накапливаются во время onEnable до успешного завершения и проверки сессии. Применение этих действий к миру не является транзакцией: если одно действие в процессе записи не удалось, уже выполненные изменения не откатываются. Прямые изменения через nativeServer вообще обходят накопление.
## Gradle-проект
Run → «Экспортировать API JAR в libraries» создаёт точный API текущего runtime и копирует путь. Существующий отличающийся файл не перезаписывается. Добавьте compileOnly files('libraries/genesis-server-api-v1.jar') в dependencies проекта. При необходимости Minecraft API также должен предоставляться его Gradle-конфигурацией.

Напишите публичный класс ServerModule в src/main/java, сохраните исходники и выполните build. Выберите режим применения: импортированный Gradle-проект предложит основной JAR из последней успешной сборки, затем полное имя класса входа. Проверяются размер и SHA-256 артефакта; для загрузки делается отдельный снимок. Несохранённые документы нужно сохранить и пересобрать.

Применяется выбранный JAR, а не произвольные текущие исходники. Если после build вы сохранили другой код, снова выполните build. Runtime не выполняет NeoForge-регистрацию @Mod, mixins/coremods, загрузку новых статических реестров или установку обычного мода в mods. Такой полноценный мод по-прежнему устанавливается стандартно с перезапуском.
## Зависимости и пределы
Локальные библиотеки берутся из libraries выбранного проекта; зависимости Gradle, не доступные в хосте, нужны там отдельными совместимыми JAR либо в подходящей self-contained сборке. Автоматического Maven/runtime classpath resolver здесь нет. Minecraft, Genesis API и другие защищённые хостовые пакеты загружаются родительским loader, их нельзя заменить своей версией.

До 16 модулей проектов одновременно в мире. Подготовка исходников наследует ограничения обычного Java snapshot; компиляция 20 секунд и вывод 64 KiB. Готовый JAR до 64 MiB, внутри применяются проверки архивных entries. Все снимки временные. Runtime не сканирует исходники каждый тик.

Multiplayer, LAN, загрузка кода с удалённого сервера, сетевые права и синхронизация клиента ещё не включены. API, адаптер мира и проверка прав отделены для будущего сетевого транспорта; сетевых обработчиков установки сейчас нет. Подключение к чужому серверу само по себе ничего не загружает и не исполняет.

## Проверки сборки 8.12.2
Выходы Gradle учитываются для конкретного запуска, включая кэшированные JAR и нестандартные каталоги. Runtime-библиотеки сохраняются в проверяемый снимок для серверного применения JAR. Успешная задача help/test не подтверждает все старые архивы в build/libs. Выдача проверяет исходники: после изменения кода или конфигурации нужна новая сборка. Обновление зависимостей защищено журналом восстановления и блокировкой проекта.

Для Embed совместимый диапазон можно задать отдельно от предпочитаемой Maven-версии. Library и локальные JAR не означают автоматическое встраивание в выпуск. Необязательные моды можно проверить с genesis.optionalMods=true в gradle.properties, затем без этого свойства. Менеджер поддерживает явные Groovy-декларации NeoGradle и один literal modId; другие проекты Gradle можно собирать напрямую с их собственным DSL зависимостей.

Серверный снимок загружает проверенные вложенные библиотеки и использует свой context classloader при всех callback. План действий проверяется до изменения мира; поддерживаемые обратимые действия компенсируются. При отказе с необратимыми действиями явно выдаётся PARTIAL_APPLY. В проверку длительности включён конструктор. Проверка времени после возврата не прерывает бесконечный Java callback: runtime выполняет доверенный код, а nativeServer обходит staging. Горячая установка на dedicated/LAN и запуск произвольного @Mod остаются отдельными возможностями: обычный совместимый JAR устанавливается с перезапуском сервера. Лимиты файлов и архивов сообщаются явно; неограниченная сложность не обещается.
